# Story Control

특정 막에 종속되지 않는 스토리 진행 관제입니다. 사용 에이전트가 화면과 공략을 판단하고,
관제가 모드·독립 타이머·입력 소유권·완료 근거·진행 손실을 관리합니다.

기본 실행은 입력 금지이며 Python 표준 라이브러리만 사용합니다. Windows 입력은
`--enable-input --target-exe 실제실행파일`로 명시적으로 켭니다. 게임 설치 경로를 추측하거나
자동으로 관리자 권한을 요청하지 않습니다. 실행은 [영문 안내](../README.md)를 따릅니다.

새 임무는 `new-plan`으로 초안을 만들고 공략·단계·완료 조건을 작성한 뒤 `draft=false`로
검증합니다. 실제 계정 자료, 공략 원문, 화면, 플레이 로그는 배포물에 포함하지 않습니다.
계획을 바꿀 때 기존 호스트를 종료하고 새 계획용 상태 디렉터리로 시작합니다.

자동 화면 판독기나 자동 완주 프로그램은 아닙니다. 입력 성공과 게임 내 성공을 구분하고,
등록 단계 수를 시간 기준 진행률로 바꾸지 않습니다. 기본 정지 키 B도 현재 구간에서 실제로
정지함을 확인했을 때만 허용합니다. 검증되지 않은 실전 성능을 주장하지 않습니다.


## 대사와 선택지 연속 진행

`story.startDialogue()`는 현재 커서 위치에서 클릭을 계속하면서 즉시 반환한다.
대사 넘김과 선택지를 함께 누를 수 있는 위치를 실제 화면으로 확인해 사용한다.
화면을 캡처해 판단하는 동안에도 클릭은 유지된다.
새 화면 확인 뒤 `story.checkDialogue(true, 근거)`로 관측을 갱신할 수 있으며,
대화 종료 또는 예상 밖 화면에서는 `story.checkDialogue(false, 근거)`로 멈춘다.
선택지가 보인다는 이유만으로 멈추지 않는다. 즉시 중지는 `story.stop()`이다.

자동 화면 판독 기능은 없다. 모델의 유지 호출 없이 계속 실행되며,
종료 판단이 도착하기 전까지는 클릭이 이어질 수 있다. Escape/F12와 창 전환도 중지한다.
기존 실행 중인 호스트에는 코드 수정이 자동 반영되지 않는다. 사용자 조작이 끝난 뒤
호스트 재시작과 어댑터 재연결이 필요하다. 자세한 호출 순서는 [API](API.md)를 따른다.


## 반복 출력 줄이기

일반 어댑터 호출은 현재 상태와 오류 중심의 짧은 응답을 반환한다.
실행 종료 확인에는 `story.status()`를 사용한다. 상세 이력이 필요할 때만
`story.report(이전커서)`를 호출한다. 기존 `report()`와 원본 저널은 보존한다.
일반 응답에서 제외한 전체 단계/이벤트/상세 시간은 `report()`로 조회할 수 있다.

대사는 한 번 연속 실행한 뒤 화면을 확인하며 유지·중지한다. 같은 보고서나 이미
받은 화면을 반복 출력하지 않는다. 근거는 확인한 전환을 짧고 구체적으로 기록한다.
전투·위험 이동의 관측을 생략해서 토큰을 줄이지 않는다. 이미지 축소나 모델 설정은
변경하지 않았으며, 응답 바이트 감소율을 전체 토큰 절감률로 해석하지 않는다.
