# 외부 도구 연결

2026-09-27

## 단일 경로

`ExternalTools`가 설치 경로, 고정 배포 해시, 실행, 작업 정의 조회, 결과 읽기를 담당한다. 캐릭터·오늘 계획·일상 화면과 내장 채팅/MCP는 `CatheryneTools`의 동일 작업을 호출한다. 기존 설치 연결은 사용자 선택 실행 파일을 사용한다. 개인 설정과 관측 자료는 런타임 DB에만 저장한다.

## 지원 범위

- BetterGI 0.66.0: 공식 배포 설치, 열기, 사용자 ScriptGroup 목록, 등록 그룹 실행, 소유 작업 중단, 공식 task_progress 조회. 관리자 실행은 Windows RunAs를 사용한다. 다른 입력 관제/스캐너와 동시 실행하지 않는다. 이미 열린 BetterGI는 실행 중인지 불명확하므로 관리 작업 시작 전에 종료해야 한다.
- Snap Hutao Remastered 1.20.3: 공식 설치, 열기, 기존 설치 연결, 선택 육성 계획과 보유 재료 읽기. 공식 로컬 pipe의 Kind 40 요청과 XXHash64 응답 검증을 사용한다. 초기 설정은 해당 앱에서 완료한다.
- 작업 로그 종료는 게임 목표 달성의 증거가 아니다. 결과 확인이 필요하다고 남기며 GOOD 원본이나 목표 완료 상태를 임의 변경하지 않는다.
- 계획을 자동으로 파밍 스크립트로 변환하는 기능은 아직 없다. 등록되지 않은 작업을 임의 생성하거나 다운로드하지 않는다.
- 두 구성요소는 시작 설정에서 선택 사항이다. 후타오 제거는 공식 Windows 설치 관리자가 담당한다.

- 공개 파일 검사, 런처 자체 검사, 패키지 자체 검사, MCP 검사 통과.
- 실제 두 공식 앱 설치 및 프로세스 실행 확인. BetterGI는 관리자 토큰을 확인했다.
- 실제 후타오 초기 설정 완료 후 런처 버튼과 AI 도구 양쪽에서 pipe 응답을 받고 로컬 저장을 확인했다. 선택 계획이 없는 실제 응답은 Data=null이며 화면에도 계획 없음으로 표시한다.
- 초기 통합 화면 확인 후 별도 제공자 메뉴를 제거했다. 수정된 런처에서 왼쪽 캘린더와 오른쪽 날짜 상세, 도구 메뉴와 오른쪽 일상 화면 배치를 실제 확인했다.
- 기존 BetterGI가 열린 경우 관리 그룹 실행이 차단됨을 확인했다.
- 현재 등록된 ScriptGroup이 없어 실제 게임 내 자동화 완주 검증은 수행하지 않았다.
- 실제 중단 시험은 실행 창의 소유권 확인 부족으로 자동 승인 검토가 거부했으며 별도 사용자 승인을 요청했다. 중단 기능의 실기 검증 완료를 주장하지 않는다.

## 사용자 흐름 수정

별도 BetterGI/후타오 메뉴는 제거했다. 설치·기존 설치 연결·원본 앱 열기는 설정 → 설치·구성요소 관리에 있다. 캐릭터와 오늘 계획의 육성 재료, 일상과 오늘 계획의 반복 작업이 같은 어댑터를 사용한다.

공식 0.66.0/1.20.3 소스에서 완전한 headless 인수를 확인하지 못했다. 호출 프로토콜은 바꾸지 않고 런처가 새로 시작한 프로세스만 관리하는 얇은 계층으로 기본 창을 숨긴다. 기존 사용자 프로세스의 창을 숨기거나 종료하지 않는다. Hutao는 실행 중이면 IPC만 호출하고, 없으면 백그라운드 시작 후 IPC 응답이 확보됐을 때 해당 새 창을 숨긴다. BetterGI는 권한이 필요한 실행을 별도 정상 RunAs 호스트에서 시작하고 작업 PID를 단일 기록에 저장한다. 초기 설정/권한 요청은 숨기지 않으며 시작 시 순간적인 창 표시까지 제거한 완전 headless라고 주장하지 않는다.

최종 설치본: 20260927-161747. 패키지 자체 검사·MCP·공개 파일 검사 통과, 설치 파일 해시 일치. 설정/링크 메뉴에 남아 있던 이전 HideMenu 이벤트 충돌을 제거했다. 재실행 후 컴퓨터 사용 도구가 이전 창 핸들을 반환하고 새 창에 `foreground window did not report a process id` 오류를 내어 마지막 설치본 화면 재확인은 완료하지 못했다. 반복 작업 상태는 화면별 상태가 아니라 공통 작업 기록에서 조회한다.


## 관제 내부 묶음 실행 (2026-09-28)

- `catheryne_game delegate`는 현재 관제의 입력권을 예약하고 기존 실행 어댑터에 넘긴 뒤 즉시 반환한다. 모델은 다음 조건부 계획을 준비할 수 있지만 입력권이 반환되기 전 다른 입력을 보낼 수 없다.
- `groups`는 `bettergi_groups`에서 조회한 작업 이름의 순서 배열이다. 기존 그룹, 설치된 `User/AutoPathing` 경로, `combat:auto`가 같은 목록과 실행 경로를 사용한다. 설정이 다른 그룹은 임의로 합치지 않는다.
- 전투의 얇은 스크립트는 공식 0.66.0 `AutoFightParam` / `dispatcher.runAutoFightTask`를 호출한다. 파티 인식과 회전은 기존 구현을 사용하고 전투 종료 감지를 켠다. 별도 음식 사용 타이머는 켜지 않는다.
- 부모 작업 ID와 파생 실행 계획은 작업 저장소에 보존한다. 실행용 그룹 파일은 종료 후 제거하며 원래 경로/그룹은 수정하지 않는다. 위임 실행에는 10분 제한이 있다.
- 중단은 관제의 사용자 제어 전환과 같은 경로를 사용한다. 실제 소유 프로세스 종료 전에는 입력권을 해제하지 않는다. 공식 실행 종료 기록은 게임 목표 완료 판정이 아니다. 새 화면을 관측하고 결과를 등록해야 한다.
- 등록된 이동 경로가 없으면 경로를 있는 것처럼 보고하지 않는다. 로컬 HUD 전투/음식 보조는 기존 보정 프로필을 요구한다.

검사: 가짜 입력을 통한 비동기 묶음 실행, 경쟁 입력 차단, 중단 후 입력권 유지, 오래된 화면/일시정지 화면 거부. 실게임 재검증은 사용자 요청으로 수행하지 않는다.


## 공통 입력권과 작업 종료

- 앱의 관제, 스캐너, 독립 자동화는 사용자 데이터의 `runtime/input.lock` 첫 바이트를 같은 OS 잠금 규칙으로 획득한다. Python 관제는 `--input-lock`으로 앱이 해석한 실제 경로를 받는다. 기존 관제 안에서 위임한 자동화는 관제가 보유한 잠금 아래의 예약을 사용하며 중복 획득하지 않는다.
- 잠금은 실제 실행 중 유지하고 프로세스 종료 시 OS가 해제한다. 스캐너를 시작하려고 기존 관제를 조용히 중단하는 경로는 제거했다. 활성 게임 작업을 먼저 중단해야 다른 독립 작업을 시작할 수 있다. 관리 밖에서 이미 실행 중인 입력 프로그램 검사도 공통 획득 함수에서 수행한다.
- 모든 작업 저장은 같은 트랜잭션에서 이전 상태를 읽고 변경한다. 종료된 작업은 지연 보고로 다시 실행 중이 되거나 다른 종료 결과로 덮어써지지 않는다. 확인 필요 상태의 재시작은 명시적 재시작 경로만 허용한다. 취소 요청은 이후 진행 보고에도 보존된다.
- 게임 준비 중 중단과 채팅 중단은 같은 함수로 처리한다. 관제 연결이 아직 없어도 취소하며, 연결된 관제는 실제 종료를 기다린다. 스캐너 예외도 실행 프로세스 정리 이후 공통 실패/취소 처리에 도달한다. 외부 자동화의 결과 수신과 프로세스 종료를 구분한다.
- 검증은 실제 게임 입력 없이 C#과 Python 테스트 프로세스의 상호 배타성, 프로세스 종료 후 해제, 종료 뒤 지연 보고, 취소와 완료 경쟁, 관제 연결 전 취소를 검사한다. 이 변경은 모델 판단 횟수나 실행 알고리즘을 바꾸지 않으므로 실게임 속도 향상 수치는 주장하지 않는다.


### 지도 중심 관측

`position:map_center`는 BetterGI 0.66.0의 `genshin.getPositionFromBigMap()`을 호출한다. 원신 좌표계로 변환된 티바트 지도 중심점이며 캐릭터 위치나 임무 목적지 자동 인식 결과가 아니다. AI는 지도의 중심과 의도한 목적지가 일치하는지 화면으로 먼저 확인한다. 결과의 `kind=map_center`와 작업 ID를 보존하며 기존 경로의 목표 좌표로 사용할 수 있다.

위치 조회 단독 실행만 읽기 전용으로 분류한다. 분류는 정규 카탈로그에서 파생해 실행 계획에 저장하고, 이 경우에만 관제가 지도 일시정지를 유지한 채 외부 실행을 예약한다. 사용자 그룹, 이동/전투와 섞인 묶음은 이 예외를 받지 않는다. 입력권, 취소, 결과 확인, 로그 저장은 기존 위임 경로를 그대로 사용한다.
