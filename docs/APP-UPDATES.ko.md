# 앱 업데이트와 GitHub 릴리스

앱 업데이트는 공개 GitHub Releases의 정식 릴리스를 사용한다. 프레임 해제 도구·스캐너·공개 게임 자료의 갱신과는 별개이며, 앱 파일의 설치·제거는 기존 Inno Setup 하나가 담당한다.

## 사용자 동작

- 일반 설정의 **앱 업데이트**에서 현재 버전, 새 버전 확인, 다운로드와 설치를 제공한다.
- 앱 실행 중 자동 확인은 6시간 캐시를 사용한다. 실패나 공개 릴리스가 없을 때는 1시간 뒤 다시 확인하며, 직접 확인은 캐시를 우회한다.
- **앱 자동 업데이트**는 기본으로 꺼져 있다. 켜면 새 버전을 다운로드하고 작업이 없는 다음 일반 실행에서 설치한다. **게임 바로 시작**은 이 설치로 지연시키지 않는다.
- 직접 설치할 때도 대화 응답·작성 중인 메시지·첨부·게임·수집·입력 작업이 있으면 앱을 종료하지 않는다. 다운로드 완료 상태를 유지해 이후 재시도할 수 있다.
- 업데이트 도우미는 원래 앱 종료를 기다리고 기존 입력 잠금과 실행 상태 판정을 재사용한다. 앱 파일을 교체하는 동안 새 앱 실행·도구 요청을 차단한다.
- 설치에는 기존 경로를 넘긴다. 다른 프로그램 강제 종료나 Windows 재부팅을 요청하지 않는다. 완료 후 홈 화면으로 다시 열며 게임 자동 실행 설정은 그대로 보존한다.
- 전송 실패는 불완전한 파일을 활성화하지 않는다. 이미 검증해 받은 설치 파일은 일시적인 확인 실패에도 유지한다. 설치 실패는 자동 재시작 반복을 막고 다음 수동 재시도로 이어진다.
- 앱 전용 업데이트 캐시의 오래된 임시 파일과 이전 다운로드만 정리한다. 계정 기록·설정·사용자 내보내기는 설치 경로 밖에 보존한다.

## 배포 규약

1. 공개 저장소를 정하고 `VERSION`을 증가시킨다. 빌드는 같은 값으로 앱과 도우미의 버전을 생성한다.
2. 앱 전체 자체 검사와 공개 자료 경계 검사를 실행한다. 통과한 실행 파일의 SHA-256으로 기존 `package.ps1`을 실행한다. `-Repository OWNER/REPO`를 지정하면 패키지의 공통 `resources.json.projectUrl`에 주소가 기록된다. 앱 코드에 저장소 이름을 하드코딩하지 않는다.
3. 같은 버전의 `vVERSION` 또는 `VERSION` 태그로 **정식 릴리스**를 만들고 `Catheryne-Setup-VERSION.exe`를 첨부한다. 초안·시험 릴리스는 업데이트 대상으로 삼지 않는다. GitHub가 계산한 asset `digest: sha256:...`가 제공돼야 한다.
4. 공개된 릴리스에서 버전·asset 이름·URL·크기·해시가 일치해야 앱이 받는다. 태그만 만들거나 GitHub의 소스 압축 파일만 올리는 것으로는 앱 배포가 되지 않는다.

`package.ps1`은 앱·도우미를 포함한 설치 파일과 빌드 가능한 소스 패키지를 구성한다. 도우미의 실행 파일은 작은 .NET Framework 프로그램이며 추가 업데이트 프레임워크나 별도 런타임을 도입하지 않는다. 패키지의 버전이 앱 실행 파일과 다르면 설치 파일 빌드를 거부한다.

공개 저장소가 아직 지정되지 않은 개발본은 '아직 공개된 앱 업데이트가 없습니다'로 표시하며 최신 버전이라고 주장하지 않는다. 비공개 저장소 인증, 시험 릴리스 채널, 버전별 차이만 받는 배포는 이번 범위에 포함하지 않는다. 소스 작성·검증·로컬 설치는 GitHub 업로드나 릴리스 공개를 수행하지 않는다.

## 검증과 한계

검사는 잘못된 주소·태그·해시·크기, 초안/시험 릴리스, 중복 asset, 숫자 버전 비교, 손상 다운로드, 대체 설치 경로, 변경된 기존 실행 파일, 실패 후 기존 상태 보존, 작업 중 보류, 재부팅·강제 종료 방지, 설치 명세의 파일 해시를 포함한다.

`test-app-updates.ps1 -Compiler ISCC_PATH`는 임시 앱·고유 시험 설치 ID로 기존 프로세스 종료 대기, 실제 Inno 설치, 설치 명세 확인, 설정 보존, 홈 재실행을 검증하고 시험 설치를 제거한다. 이번 검토에서는 공식 Inno 6.7.3을 서명과 공개 digest로 검증한 뒤 임시 휴대용 모드로 사용해 이 검사를 통과했다. 전역 빌드 도구 설치나 실제 앱·게임 조작은 수행하지 않는다.

SHA-256은 GitHub 릴리스에서 받은 설치 파일의 무결성을 확인한다. 배포 저장소와 릴리스의 권한 관리는 게시자의 책임이다. 실제 새 릴리스가 게시되기 전에는 공개 배포의 처음부터 끝까지 작동 여부를 검증했다고 주장하지 않는다.
