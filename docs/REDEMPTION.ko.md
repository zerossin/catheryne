# 리딤코드 연동

조사/구현 확인: 2026-09-29. 원신 글로벌 서버 대상. 아래 기능은 커뮤니티 연동이며 HoYoverse 공인 제품이라는 의미가 아니다.

## 선택과 근거

- [genshin.py](https://github.com/seriaati/genshin.py): 2021년부터 개발된 MIT 라이선스 HoYoLAB 라이브러리. 조회 당시 478 stars, 84 forks. 원 제작자에서 seriaati로 유지보수 이전. [등록 구현](https://github.com/seriaati/genshin.py/blob/master/genshin/client/components/hoyolab.py), [API 주소](https://github.com/seriaati/genshin.py/blob/master/genshin/client/routes.py), [응답 분류](https://github.com/seriaati/genshin.py/blob/master/genshin/errors.py)를 프로토콜 확인에 사용했다. Python 패키지나 소스 코드를 앱에 포함하지 않는다. 기존 C# 네트워크/암호화 저장소에서 공식 웹 API를 호출한다.
- [hoyo-codes](https://github.com/seriaati/hoyo-codes): GPL-3.0 공개 코드 목록 서비스. 조회 당시 41 stars, 3 forks. [공개 API](https://hoyo-codes.seria.moe/codes?game=genshin)를 익명 조회한다. 서버를 설치하거나 GPL 코드를 앱에 포함하지 않는다. 실제 응답은 `{game: "genshin", codes: [...]}`이며 game/status/code/rewards를 검증한다. 전체 코드·특정 계정의 수령 가능성을 보장하는 서비스는 아니다.
- [hoyo-redeem-codes-script](https://github.com/hashblen/hoyo-redeem-codes-script): Google Apps Script와 수동 쿠키 복사 방식. 현재 앱의 로그인·로컬 저장 구조에 더 잘 맞는 위 경로를 선택했다.
- [SnapHutaoArchive](https://github.com/DGP-Studio/SnapHutaoArchive): 원본 저장소가 보관 상태여서 신규 글로벌 리딤 기능의 의존성으로 선택하지 않았다.

공개 코드 후보와 계정별 공식 등록 결과는 서로 다르다. 모험 등급·서버·사용 이력·만료·사용 횟수 제한은 실제 응답으로만 판정한다. 보상 설명은 제공처 원문이며 보유 원석이나 실제 우편 수령량으로 환산하지 않는다.

## 사용자 흐름

일상 화면의 출석 아래 **리딤코드**에서 공식 리딤 페이지에 로그인한다. 쿠키 수동 입력은 없다. 연결된 원신 계정이 하나면 선택하고, 여러 개면 사용자가 계정을 선택한다. 출석 로그인과 리딤 인증은 도메인/토큰 요건이 달라 별도 연결을 사용한다.

- 코드 새로고침: 로그인 없이 공개 목록을 조회한다.
- 미등록 코드 모두 등록: 선택 계정에서 순차 등록한다. 서버가 확인한 이미 사용/만료/무효/지역 제한 결과는 재시도하지 않는다.
- 새 리딤코드 자동 등록: 기본은 꺼짐. 켜면 기존 일상 실행 프로세스에서 30분마다 조회·등록한다. 등록 요청 사이에 6초 간격을 둔다. 등급 미달은 하루 뒤 자동 재시도한다.
- 창 종료 뒤 실행: 기존 백그라운드 실행 설정을 사용한다. PC 종료/절전 중이나 프로세스가 종료된 동안에는 실행하지 않는다. 다시 실행하면 저장된 마지막 시도로부터 경과 시간을 확인한다.
- 코드와 등록 결과: 보상 설명과 코드별 상태, 확인 시각/응답 번호 툴팁을 제공한다. 인증 실패·추가 확인·통신 실패는 접힌 목록 밖에도 표시한다.
- 리딤 연결 해제: 자동 등록을 끄고 암호화 인증을 삭제한다. 기록은 보존한다. 계정을 바꾸면 자동 등록을 다시 켜야 한다. 별도의 출석 연결/설정에는 영향을 주지 않는다.

## 단일 실행 경로와 개인정보

`RedemptionService`를 화면, 백그라운드 타이머, AI 작업이 공유한다. `redemption.refresh`, `redemption.redeem`, `redemption.disconnect`, `daily.configure(automaticRedeem)`와 `redemption` 조회가 동일한 원본을 사용한다.

인증은 기존 Windows DPAPI 저장소에 보관한다. 공개 목록 요청은 쿠키나 UID를 전송하지 않는다. 인증 요청은 고정 HoYoverse 호스트만 사용하며 자동 리디렉션을 금지한다. 결과/AI 조회에는 쿠키를 포함하지 않는다. 원격 오류 본문이나 예외의 요청 URL을 기록하지 않는다. 보관함/공개 저장소에 계정 인증을 저장하지 않는다.

계정 키는 서버+UID이며 코드별 공식 응답을 기존 관측 저장소에 기록한다. 프로세스 간 파일 잠금으로 GUI/백그라운드/AI 동시 실행을 막고 자동 시도 간격을 영속화한다. 연결 해제/계정 변경/자동화 해제/종료는 다음 요청 전에 재확인한다. 이미 전송한 요청은 취소되어도 서버에서 처리될 수 있으므로 다음 실행에서 공식 결과를 다시 확인한다.

## 검증과 남은 확인

빌드, 가짜 응답 테스트, 번역 검사, 공개 소스 개인정보 검사를 수행한다. 테스트는 목록 응답 구조, 중복 제거, 계정별 기록, 재시도, 로그인 오류 중단, 동시 실행 잠금, 연결 해제, 종료 취소와 결과의 인증정보 제외를 확인한다.

공개 목록의 실제 조회는 확인했다. 사용자 계정의 공식 로그인·코드 등록과 우편 수령은 아직 실기 검증하지 않았다. 설치본 교체, Windows 시작 등록, 사용자 자동화 활성화, 원격 push는 이번 구현에서 수행하지 않는다.
