## 제품 원칙

사용자의 계정과 진행 상황을 이해하고, 사용자가 맡긴 목표를 게임 조작으로 수행하는 원신 AI 플레이 도우미. 실행이 중심이고 계정 기록·추천·UI는 실행의 기반이다. 기존 오픈소스의 수집·최적화·실행 기능을 활용하고, 고유 가치는 조작 노하우·도구 통합·일관된 사용자 경험에 둔다.

- 목표 → 계획 → 현재 관측 → 제한된 실행 → 결과 검증 → 기록 갱신.
- AI가 기다리거나 생각하는 동안 승인된 제한 작업과 감시는 독립적으로 실행된다. 모든 상황에서 무조건 계속 실행하지 않는다.
- 입력 전송 성공은 목표 완료가 아니다. 완료에는 근거가 필요하다.
- 미수집·오래된 자료·불확실한 관측을 미보유 또는 확정 사실로 바꾸지 않는다.
- 사용자는 즉시 입력 중지 및 조작권 반환을 요구할 수 있다.
- 앱을 처음 설치한 사람에게 개발 런타임 설치·경로 편집을 요구하지 않는다. AI 제공자의 인증·구독·기능 제약은 별도로 명확히 표시한다.

## 실행 구조와 책임

Desktop와 AI는 같은 core API의 클라이언트다. UI에서 시작한 작업과 AI가 시작한 작업은 동일한 작업 ID와 실행 기록을 가진다. 앱이 닫혀도 작업을 계속할지는 명시적인 사용자 설정으로 결정하며, 임의로 기존 종료 동작을 바꾸지 않는다.

초기는 기존 WPF 화면과 Python 실행 서비스를 유지한다. 프레임워크 전면 교체나 범용 플러그인 시장은 만들지 않는다. 어댑터 목록과 지원 버전을 명시적으로 관리한다. IPC는 로컬 전용·인증된 연결이며 임의 명령 실행 API를 노출하지 않는다.

### 단일 실행 관리자

- 동시에 하나의 도구만 게임 입력 권한을 가진다. 각 입력 작업은 소유자·유효 기간·작업 ID·중지 경로를 가진다.
- Computer Use 직접 입력도 실행 관리자에 시작·종료를 등록한다.
- 외부 스캐너는 실행 기간 전체를 독점 작업으로 취급한다. 종료를 확인하기 전 다른 입력을 시작하지 않는다.
- 관리 밖의 프로세스/사용자 입력까지 OS 수준에서 차단할 수 있다고 주장하지 않는다. 충돌이 감지되면 관리 입력을 멈추고 상태를 표시한다.
- 재시작 시 이전 입력 권한은 무효. 화면과 진행 상태를 재확인한 후 재개한다.
- 독립 시계가 경과 시간·마지막 관측 나이·AI 응답 대기·작업 정체를 기록한다. CPU 모델 추론 시간과 전체 대기 시간을 혼동하지 않는다.
- 스토리의 전투·대화·이동·퍼즐 등 모드는 관측 근거와 신뢰 수준을 가진다. AI 분류가 늦는 긴급 상황은 로컬 감시와 해당 모드의 중단 조건으로 처리한다.

### AI 역할

AI는 목표 분해, 자료 조회, 다음 제한 작업 선택, 예외 재계획을 수행한다. 반복 입력·타이머·명확한 화면 인식은 로컬 도구가 수행한다. 제공자 연결은 사용 가능한 공식 도구/인증 경로를 사용하며 모든 외부 AI 앱을 무인 제어할 수 있다고 전제하지 않는다. AI 미연결 시에도 계정 조회·자료 수집·기본 게임 실행은 가능하다.

### 조작 노하우

playbook은 사전 조건, 관측 항목, 실행 수단, 시간 제한, 중지 조건, 성공 근거, 복구 절차, 검증 게임 버전을 가진다. 화면 위치를 영구적인 사실로 가정하지 않는다. 공략의 단계 완료와 계정 사실 변경은 검증된 결과만 반영한다. 장비 잠금 해제·소모·재련 등은 단순 장착과 별개의 명시적 행동으로 취급한다.

## 정규 데이터 모델

- Profile: 앱 내부 UUID, 표시 이름, 사용자가 확인한 게임 계정 식별, 활성 상태. 프로필 자동 병합 금지.
- AccountSnapshot: 원본 해시, 출처, 수집 범위, 시각, 형식 버전. GOOD 원본은 불변 보관.
- Item: 개별 무기·성유물. 종류 키만으로 합치지 않는다. 재수집 매칭이 불명확하면 별도 확인 대상으로 둔다.
- Observation: 관측 대상, 값, 시각, 근거, 확인 수준. 화면/파일/사용자 진술의 출처 구분.
- Task: 목표, 프로필, 계획 버전, 현재 단계, 상태, 완료 근거.
- Action: 의도, 실행 주체, 입력 권한, 제한 시간, 결과와 후속 관측.
- Recommendation: 기준 스냅샷, 자료 버전, 조건, 근거. 보유 사실과 분리한다.

원본에서 읽기용 계정 뷰를 생성한다. UI와 AI가 별도 보유표를 저장하지 않는다. 기본 상태는 대기·실행 중·일시 정지·사용자 조작·확인 필요·완료·실패·취소. 게임 모드와 작업 상태는 서로 다른 필드다.

## 사용자 저장 공간

초기는 기존 표준 `%LOCALAPPDATA%/GenshinCompanion`을 유지한다. 이름 변경만을 위해 기존 경로를 즉시 옮기지 않는다. 향후 경로 이동은 백업·검증·되돌리기가 있는 일회성 마이그레이션으로 한다.

```text
<사용자 데이터>/
  settings.json
  profiles/<uuid>/
    profile.json
    originals/          GOOD·업적 수집 등 불변 원본
    state/              원본 참조·확정 기록·계획
    tasks/<task-id>/    행동·관측·체크포인트
    backups/
  cache/                삭제해도 다시 생성 가능한 자료
  runtime/              실행 중 연결 정보
```

JSON과 원자적 파일 교체, 순번 있는 이벤트 기록부터 시작한다. 작업 중 의미 있는 단계마다 체크포인트를 저장하고 손상된 마지막 기록은 완료로 승격하지 않는다. 사진은 필요한 근거에만 저장하고 보존 설정을 제공한다. 인증정보는 계정 내보내기에 포함하지 않으며 OS 보안 저장소를 사용한다. Git ignore만을 개인정보 분리 수단으로 삼지 않는다. 백업 가져오기 전에 형식과 계정을 검증한다.

## 사용자 화면

왼쪽: 홈 / 플레이 / 계정 / 업적 / 도구 / 설정. 기존 실험의 스토리는 플레이 안으로, 캐릭터는 계정 안으로 정리하는 최종안이다. 아직 이 메뉴 변경은 적용하지 않았다.

- 홈: 목표 입력, 실행 가능 여부, 현재 작업, 최근 결과.
- 플레이: 스토리·업적 수행·장비 장착 등의 목표, 단계, 현재 모드, 근거, 경과 시간.
- 계정: 캐릭터·무기·성유물 및 장착 관계, 수집 범위와 시각, 일반 추천과 보유 기반 추천.
- 업적: 달성 현황, 미확인 항목, 수집/검증/외부 반영, 수행 목표 만들기.
- 도구: 기존 언락커·채널·수집기 설치 상태와 실행 연결.
- 전역 작업 표시: 입력 소유자와 항상 접근 가능한 중지·직접 조작. 여러 화면에서 같은 작업 상태를 읽는다.

설치 후 게임 위치 확인 → 프로필 생성 → 원하는 목표 선택. 기능별 구성요소는 필요할 때만 설치하며, 데이터 출처와 준비 상태를 표시한다. 임의 예상 백분율 대신 확인된 단계와 측정 가능한 작업량을 표시한다.

## 외부 도구 채택 기준

각 후보는 라이선스·재배포 허용·유지보수 상태·지원 게임 버전·입출력 형식·중단 가능성·검증 자료로 평가한다. 특정 제품 채택은 조사 후 결정한다. Computer Use는 오픈소스라고 일괄 분류하지 않으며 제공자의 이용·배포 조건을 따른다. 엑셀 추천 자료도 공개 열람 가능과 재배포 허용을 구분한다. 출처·버전·적용 조건 없이 추천 카탈로그로 복제하지 않는다.

## 단계별 도입 및 합격 기준

1. 정규 원본 통합: 운영 소스와 실험 차이를 비교하고 저장소 경로를 확정. 개인 파일 배포 제외, 기존 실행 기능 회귀 통과.
2. 계정 기반: 다중 프로필·GOOD 조회·원본 보존. 중복 무기 보존, 부분 자료가 전체를 덮지 않음, 백업 복원 검증.
3. 실행 통합: 기존 story-control을 단일 실행 경로로 연결. 가짜 입력으로 중지·소유권·AI 지연·재시작을 검증한 뒤 실제 입력 검증.
4. 첫 완결 흐름: 목표 하나를 요청 → 실행 → 실제 결과 확인 → 기록 갱신. 무기 장착은 개별 무기·장착자·사후 화면까지 확인.
5. 업적/스토리 확장: 중간 저장·증분 수집·불명확 항목 재확인. 기존 약 35분 수집 대비 같은 계정에서 3분30초 이내를 목표로 삼되, 아직 달성한 성능이 아님.
6. 추천·배포: 추천 출처 검증, 기존 최적화 도구 연결, 깨끗한 Windows 환경에서 단일 설치·업데이트·복원 검증.

속도 평가는 최초 입력까지 시간, 관측 나이, 긴급 상황 반응, 입력 중지 지연, 전체 작업 시간, 성공률을 분리한다. 게임 업데이트 시 잘못된 완료 0, 검증 계정 ID별 누락 0, 중단/재개 결과 일치, 무관한 계정 데이터 보존을 확인한다. 로컬 중지 응답 200ms 이하를 초기 목표로 두되 외부 API 호출의 취소 불가 구간은 별도 측정한다.
