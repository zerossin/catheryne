# Catheryne 목표 완수와 오늘 할 일 — 기준 설계

2026-09-26. 사용자 요청으로 기록한 제품 방향. 이 문서는 목표 시스템의 기준 설계이며 구현 완료 선언이 아니다. 기존 ARCHITECTURE와 PRODUCT-FLOW의 목표·메뉴 관련 설명보다 이 문서를 우선한다. 아래 구현 현황은 단계별로 갱신한다. 전체 설계가 모두 구현된 것은 아니다.

## 제품 정의와 불변 조건

사용자가 원하는 결과와 제한을 지정하면, 계정 상태와 기존 도구를 조합해 수행하고 실제 달성을 확인하는 원신 AI 플레이 도우미. 통합·AI 친화·사용자 편의가 핵심이다. 기본 사용은 설치 → 필요한 연결 → 목표 선택/자연어 요청 → 실행이며 전문 옵션은 접힌 고급 관리에 둔다.

- 스크립트 종료가 아니라 목표 조건의 관측상 충족이 완료다. 미지원·불확실·대기는 완료가 아니다.
- 자연어, UI, MCP는 같은 GoalRequest와 TaskPlan의 진입점이다. 별도 일상 엔진이나 육성 엔진을 만들지 않는다.
- 기존 Task는 실행 인스턴스다. GoalRequest에 안정적인 목표 ID·완료 조건·수명·정책을 부여하고 TaskPlan/Task가 이를 참조한다. 의미가 겹치는 Job/Mission/Project를 새로 만들지 않는다.
- AI는 의도 해석·도구 선택·예외 재계획, 계산기는 수량·일정·예산, 로컬 실행기는 반복 조작·감시·증거 수집을 맡는다.
- 보유량에는 출처·범위·시각을 붙인다. 인식 실패를 0으로 바꾸지 않는다. 장비 GOOD만으로 일반 배낭 전체가 수집됐다고 가정하지 않는다.
- 사용자 데이터는 저장소 밖에 둔다. 공개 자료와 개인 재고/목표/플레이 기록을 혼합하지 않는다.

## 목표·일과·자원은 서로 다른 역할

1. 목표: 원하는 최종 상태. 예: 벤티 레벨 90에 필요한 재료 확보, 실제 벤티 레벨 90 달성, 지정 임무 완료, 특정 업적 달성. 재료 확보와 실제 육성은 별개 완료 조건이다.
2. 반복 정책: 언제 무엇을 확인할지. 예: 오늘 일일 보상 수령, 탐사 재파견, 허용 시간 내 레진 활용. 매 주기 목표를 동일 모델로 생성하며 계정+서버 리셋 주기+정책으로 중복 생성 방지.
3. 자원: 레진·시간·모라·경험치·재료·선계 화폐 등. 레진 소비는 기본적으로 목적을 위한 수단이다. 사용자가 명시하면 넘침 방지 자체도 독립 목표가 될 수 있다.
4. 오늘 계획: 모든 활성 목표와 반복 정책을 현재 제약 안에서 실행 순서로 투영한 TaskPlan. 원본 목표를 복제하지 않는다.

하나의 실행이 여러 목표에 기여할 수 있다. 같은 비경 보상을 육성 재료와 기행 조건에 반영하되 레진 지출과 획득 아이템 이벤트는 한 번만 기록한다. 재고 예약은 목표별 우선순위에 따라 계산하고 같은 재료를 두 목표가 동시에 확보한 것으로 계산하지 않는다. 재계획 시 실제 재고·진행에서 남은 수요를 재계산한다.

## 화면: 최상위 탭을 늘리지 않는다

- 홈: 오늘 할 일 / 목표. 오늘 실행 버튼, 활성 장기 목표와 우선순위, 준비 상태, 예상 자원 소모, 현재 작업, 결과. 자연어로 만든 목표도 같은 목록에 표시한다.
- 화면·성능: FPS, 해상도, 화면 모드, 언락커 활성, 실행에 필요한 표시 환경. 기존 기능 유지.
- 스토리: 임무·선행 조건·진행 현황·공략·수행 목표. 실제 지원 범위를 표시한다.
- 캐릭터: 현황/장비/성유물 수집, 공략, 육성 목표. 목표 레벨·특성·무기·성유물 기준 설정과 부족분 표시. 재료/모라/경험치를 별도 최상위 메뉴로 나누지 않는다.
- 업적: 수집·완료 현황·공략·수행 목표. 현황 미수집과 미달성 구분.
- 일상: 반복 작업 설정, 보상 수령, HoYoLAB 출석·레진 현황·알림. 게임 내 일일 보상과 웹 출석은 별개 작업임을 명시한다.
- 링크: 원본 프로젝트와 유용한 페이지의 가로 아이콘 메뉴 유지. 실행과 버전 관리의 대체 화면으로 만들지 않는다.
- 설정: 설치 경로·채널·언어·AI 연결·개인 데이터·권한·외부 도구 버전 관리. 목표의 개별 설정을 몰아넣지 않는다.
- 우측 공통 상세 화면: 육성 부족분, 오늘 계획 근거, 실행 현황/실패, 캐릭터 공략. 어느 메뉴에서 열든 같은 목표/실행 ID를 참조한다.
- 전역 실행 표시: 현재 목표/행동/게임 모드, 실제 경과 시간, AI 대기, 중지·직접 조작·재개. 홈을 떠나도 유지한다.

## 첫 사용과 매일 사용

초기: 게임 위치 자동 탐지 → 사용 가능한 도구 자동 준비 → 필요한 AI/계정 연결 → 한 화면에서 자원 사용 원칙을 정한다. 계정 로그인이 필요한 흐름은 사용자가 수행한다. 이후 동일 원칙을 매번 다시 묻지 않는다.

사용자가 게임을 켠 뒤 “오늘 할 일 수행해”라고 하거나 홈의 오늘 실행을 누르는 흐름을 우선 지원한다. 게임이 꺼져 있으면 설정된 실행 채널로 런처가 시작할 수 있게 하되 로그인/업데이트/권한 대기는 상태로 표시한다. 로그인 장벽을 임의로 우회하지 않는다.

1. 활성 계정·게임 상태·지원 도구·기존 실행 여부를 확인.
2. 목표에 필요한 상태만 갱신. 매일 전체 장비 스캔을 강제하지 않음.
3. 반복 정책과 장기 목표를 합쳐 오늘 계획 산출. 사용자는 펼치면 이유와 비용을 볼 수 있으나 기본 흐름에 매번 계획 승인 단계를 추가하지 않는다.
4. 허용 범위에서 실행하고 단계별 실측/완료 근거 기록.
5. 오늘 한 일, 남은 목표, 기다리는 이유, 다음 가능한 시점을 보고한다. 오늘 실행 종료와 장기 목표 완수를 구분한다.

장기 목표는 선택 사항이다. 없으면 사용자가 켜 둔 일상/수령만 처리한다. 레진 소모 대상이 없는데 임의 캐릭터·성유물 비경을 선택하지 않는다. 첫 설정에서 지정한 기본 소모처가 있으면 사용하고, 없으면 할당 필요 상태로 둔다.

## 계획 계산과 우선순위

기본 판단 순서: 사용자 제한 → 만료/리셋 기한 → 지정 목표 우선순위 → 오늘만 가능한 획득처 → 자원 넘침과 이동 비용. 동률은 결정적 규칙으로 처리하고 사용자가 순서를 바꿀 수 있게 한다. 재계획은 관측 변화·실패·리셋·사용자 수정 등 의미 있는 사건에서만 한다.

- 레벨/돌파/특성/무기: 현재 상태부터 목표까지의 정확한 필요량을 검증된 카탈로그로 계산. 합성은 정수 레시피와 낮은 등급의 보존 필요를 반영하고 불확실한 보너스 획득을 필수 수량에서 미리 빼지 않는다.
- 모라/경험치: 부수적으로 딸려오는 소비 자원이므로 같은 부족분 계산에 포함. 부족하고 허용됐다면 지맥 작업을 배정한다.
- 요일 제한: 계정 서버의 날짜·리셋 시각과 콘텐츠 개방 조건을 사용. PC 자정으로 대체하지 않는다. 오늘 불가능한 재료는 대기하고 다른 허용 작업을 수행한다.
- 특산물/몬스터 재료: 재생 대기·지역 개방·검증된 경로 지원을 반영. 타인 월드 진입을 기본 행동으로 포함하지 않는다.
- 성유물: 무한한 “좋은 것”을 완료 조건으로 삼지 않는다. 슬롯/주옵션 등 측정 가능한 기준과 레진/기간 상한을 지정. 상한 도달은 목표 성공과 구분한다. 장비 평가는 기존 최적화 도구를 활용한다.
- 자원 정책: 원석/약한 레진/희귀 화폐/잠긴 장비 소비 등은 별도 허용 범위. 일반 레진 사용 권한이 이들 사용 권한을 의미하지 않는다. 자동 지출·분해·강화는 이번 설계로 활성화하지 않는다.

## 일상 범위: 수령과 미션 수행을 분리

| 항목 | 계획상 취급 | 지원/완료 원칙 |
| --- | --- | --- |
| HoYoLAB 출석 | 웹 일상 | 기존 구현 활용, 게임 입력 없이 독립 가능 |
| 일일 보상 | 게임 일상 | 수령 조건 확인 후 수령, 일일 의뢰 직접 수행과 구분 |
| 탐사 | 수령+재파견 정책 | 부족 재료 우선 등 규칙과 보유 캐릭터 제약 반영 |
| 선계 | 수령/구매/제작을 분리 | 수령만 허용해도 구매·제작은 실행하지 않음 |
| 레진 | 장기 목표에 배정하는 자원 | 지정 기본 소모처 또는 목표에만 배정 |
| 기행 보상 | 받을 수 있는 보상 수령 | 선택 상자는 사용자 기준 없으면 확인 필요 |
| 기행 미션 | 선택한 반복 목표 | 모든 미션을 자동 수행한다고 약속하지 않음. 다른 작업의 자연스러운 달성을 우선 집계 |
| 주간 작업 | 별도 주기 정책 | 주간 보스·기한·예산과 지원 여부 확인 |
| 알림 | 결과/막힘/자원 상태 | 의미 있는 변화 중심, 정상 반복 중 불필요한 알림 억제 |

표는 목표 제품 범위이지 현재 실행 지원 목록이 아니다. 각 작업은 지원 도구·게임 버전·언어·해상도·검증 결과를 가진 capability로 공개하며 미지원은 숨기거나 명시한다. “오늘 할 일”이 원신 모든 콘텐츠 수행을 의미하지 않는다.

## 실행과 중단

게임 입력은 한 관리자만 소유한다. BetterGI, Computer Use, 스캐너를 동시에 입력시키지 않는다. AI 판단 중에는 허가된 범위·시간·목표량 안의 로컬 작업만 계속된다. 모델 연결/사용량 한도 때문에 중단되면 체크포인트와 다음 조치를 보존한다. 무제한 매크로로 대체하지 않는다.

계획은 의존성이 있는 작업들의 목록으로 표현한다. 실행 상태는 대기/실행/일시정지/확인필요/완료/실패/취소를 재사용하고, 대기 사유(리젠·레진·요일·선행임무·미지원)를 분리한다. 재시작 후 이전 키 입력을 이어 보내지 않고 게임과 재고를 다시 확인한다.

## 도구 통합과 조사 결론

BetterGI는 전용 반복 실행 후보, Snap Hutao는 육성 계산/데이터 연동 후보다. 자동 채택이나 이미 완성된 연결로 취급하지 않는다. 각 어댑터는 준비 상태, 실행 요청, 진행, 중지, 결과 증거를 공통 계약에 맞춘다. 외부 도구 업데이트는 실행 중 적용하지 않는다.

2026-09-26 소스 조사: Hutao에는 QueryCurrentCultivationProject로 Entries/InventoryItems와 재료별 Count/RankLevel/Monsters를 제공하는 코드가 있다. 공식 BetterGI main 0af68c2 전체 검색에서 그 전용 요청의 소비 경로는 확인되지 않았다. 별도 포크/외부 연결의 부재까지 증명한 것은 아니다. 두 공식 앱을 설치하면 목표 수집이 자동으로 연결된다고 안내하지 않는다.

BetterGI의 별도 “角色养成一条龙” 스크립트는 수동 입력 목표량과 게임 내 보유량을 비교해 지원 보스/비경 반복, 중단·완료 기록을 제공한다. 지역 특산물·일반 몬스터 재료·합성·레벨업은 설명상 제외한다. “批量讨伐角色养成材料BOSS”는 토벌 횟수 기반 재개를 제공하며 설명상 무상의 바람 미지원이다. 각각의 지원 범위를 전체 BetterGI의 한계로 일반화하지 않는다. 이번 조사는 소스 검토이며 실제 게임 성능 검증은 하지 않았다.

## 구현 순서와 검증 기준

1. 현재 코드와 설계의 차이를 명시한 기능표. 기존 런처·스캔·일상·계정·스토리 관제 보존. 단일 목표/정책/계획/실행 참조 계약부터 정리.
2. 작고 완결된 오늘 실행: 이미 지원되는 읽기/웹 출석 흐름과 하나의 검증된 게임 작업을 같은 실행 기록에 연결. 사용자 설정을 보존하며 중지·재개·계정 일치 검증.
3. 하나의 육성 목표: 현재 재고 → 부족분 → 지원 획득처 한 종류 → 재관측 → 정확한 종료. 첫 실증에는 지원되는 목표를 선택하고 벤티 등 특정 캐릭터를 미리 보장하지 않는다.
4. 여러 목표의 재고/레진 배분, 모라·경험치, 요일·리젠·기간·예산과 오늘 계획.
5. 탐사·선계·기행·주간 작업을 각각 별도 capability로 실증 후 확대. 실제 목표 달성 확인 없는 범용 자동화 광고 금지.
6. 새 사용자/Plus 등 일반 AI 연결 환경에서 설치→목표→완료 검증. 모델 비용과 관제 지연을 측정하고 작은 모델/로컬 실행으로 분담.

지표: 목표 완수율, 잘못된 완료 수, 사용자 개입 횟수, 중지 지연, 재시작 후 중복 지출, 재고 오차, 임무당 AI 사용량, 첫 실행까지 시간. “기능 버튼 수”는 성공 지표가 아니다. 분모 없는 완료 퍼센트와 측정하지 않은 예상 시간을 표시하지 않는다.


## 구현 현황 — 2026-09-26 런처 뼈대

- 홈 `목표와 오늘 할 일`, 기존 메뉴의 공통 진입 버튼 → 같은 목표 화면. 우측 공통 상세에 목표 등록·오늘 계획.
- 개인 SQLite의 observations(kind=goal-state, profile=default)에 버전 1 GoalState 스냅샷을 저장한다. BEGIN IMMEDIATE로 최신 상태를 읽고 변경 후 커밋하므로 서로 다른 화면/프로세스의 오래된 사본이 덮어쓰지 않는다. 목표 ID, 사용자 순서, 보류, 선언 시각과 레진 상한을 보존한다. 별도 일상/육성 목표 DB는 만들지 않는다. UI는 현재 default 프로필만 지원한다.
- GoalRequest는 자유 서술 선언 단계다. 완료 조건의 구조화·검증, 반복 정책, 기존 TaskPlan과 연결하는 변환기는 **미구현**이다. 등록 상태는 준비 대기로 표시하며 완료 버튼이나 실행 버튼을 만들지 않았다.
- GoalPlanner.Preview는 실행기 연결 전의 순수 계산 경계다. 기존 TaskPlan에서 추출할 작업 ID/목표 ID/비용/관측 여부/해금 시각/서버 요일을 받는다. 모라·경험치·비경·보스는 공통 레진 예산을 사용한다. 중복 작업 ID는 거절하며 한 실행의 다중 목표 기여는 후속 어댑터가 하나의 TaskPlan 작업으로 합쳐야 한다. 현재 실제 UI 목표를 이 계산기에 자동 분해하지는 않는다.
- 알려진 현재 레진과 사용 한도의 최솟값만 예약한다. 미수집 재고·미확인 비용·미확인 서버 날짜·미연결 실행기는 실행 가능한 것으로 바꾸지 않는다. 요일 대기, 리젠 대기, 레진 부족을 구분한다. PC 요일을 게임 서버 요일로 사용하지 않는다. 모든 채집을 48시간으로 고정하지 않고 검증된 획득처별 NotBefore를 받는다.
- MCP goal_query는 동일 DB를 읽기 전용 조회한다. 자동 계획/실행 capability는 false다. 타 프로필을 default로 대체하지 않는다.
- 다음 단계: 검증된 육성 카탈로그와 배낭 관측 → 수량/합성/자원 예약 → 기존 TaskPlan 어댑터 → BetterGI 능력 검증 및 단일 입력 소유권 → 관측 근거 완료. 계획 캐시나 실행기를 별도 엔진으로 복제하지 않는다.

## 선택형 모드 지원

최상위 메뉴를 추가하지 않고 `화면·성능 → 세부 설정 → 모드 관리`의 우측 상세를 사용한다. 기존 XXMI 실행 파일 연결·열기만 지원하며 경로는 개인 settings.json에 저장한다. 원신 기본 실행 경로는 변경하지 않는다. XXMI 원본 도구가 설치/업데이트를 담당한다. 실행기 경로가 존재한다는 표시가 호환성 검증을 의미하지 않는다.

사용자가 제공한 2023년 글은 수요 참고 자료다. 투명도 제거/어두운 로딩은 원본 페이지 링크 후보이며 현재 호환성/재배포 조건은 미확인이다. UID 숨기기는 최신 검증 배포처를 찾기 전 다운로드 링크를 등록하지 않는다. 자동 설치, 모드 파일 변경, 폴더 이동, DLL 주입은 구현하지 않았다.

조사 출처: [XXMI Launcher](https://github.com/SpectrumQT/XXMI-Launcher), [투명도 필터](https://gamebanana.com/mods/406659), [어두운 로딩](https://gamebanana.com/mods/436284). GameBanana는 본문/현재 라이선스를 확인하지 못했으므로 도입 검증으로 간주하지 않는다.
