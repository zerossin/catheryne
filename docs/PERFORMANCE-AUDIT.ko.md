# 경량화 및 코드 구조 점검 — 2026-09-27

## 범위

데스크톱 채팅 렌더링, 시간 기록, 패널 공통화, 주기 조회, 외부 도구 상태 갱신, 실행 프로세스 수명, 패키지 의존성을 확인했다. 기존 기능의 삭제나 저장 형식 교체는 하지 않았다. 기존 작업 트리의 다른 변경은 보존했다. 저장소 전체에 결함이 없다는 보증이나 모든 게임 기능의 실사용 검증은 아니다.

## 측정과 검사

- Markdown 241블록, 40회 문자열 증가 갱신: 기존 전체 재생성을 모사한 비교 959ms, 기존 블록 재사용 76ms. 첫 블록 객체 보존 확인. 일회성 합성 측정이며 전체 앱 속도나 장시간 메모리 수치가 아니다.
- 데스크톱 패키지 자체 검사 통과. 시간의 재실행 복원, 대화 간 격리, 서버 시간 보존, 잘못된 숫자 시간, Markdown 객체 재사용과 문단 간격 검사 포함.
- story-control 무입력 테스트 48개 통과.
- MCP 초기화, 도구 목록 및 호출 회귀 검사 통과.
- 공개 소스 개인정보 경계 검사 통과.
- 설치본 실행과 기존 대화의 ‘시간 미기록’ 데이터 확인. 장시간 대화 스트리밍 부하 수치는 측정하지 않았다.

## 유지한 의존성과 구조

- Markdig는 Markdown 파서, WebView2는 로그인 화면에 실제 사용한다. 삭제하면 기능이 손상되므로 유지했다. 복원 스크립트의 패키지 버전과 다운로드 해시가 고정되어 있다. 이번 점검은 알려진 취약점 데이터베이스 대조가 아니다.
- SQLite는 Windows 제공 라이브러리를 사용한다. 별도 서버나 DB 패키지를 추가하지 않았다.
- 게임 조작 대기/외부 프로세스 대기는 도메인 작업 경로에 필요하므로 단순히 Sleep/Wait 검색 결과만으로 제거하지 않았다.
- 캘린더 등 공통 패널과 외부 어댑터는 동일 저장소와 실행 경로를 유지했다.

## 앱 전체 탐색 및 조회 수정

- PanelNavigation으로 왼쪽/오른쪽 화면별 단일 활성 경로를 적용했다. 일상 뒤에서 작업 기록이 열리던 겹침, 이전 닫기 애니메이션이 새 화면을 숨기던 경합을 제거했다.
- 같은 상세 경로의 새 콘텐츠를 무시하던 DetailPanel.Show를 수정했다. 공통 Shell은 유지하고 콘텐츠를 교체한다.
- 일반 설정과 화면 설정도 공통 Shell을 사용한다. 모든 뒤로가기와 구형 캐릭터 탭을 제거했다. 설치 관리 버튼은 같은 스크롤 내용에 있어 구성요소 카드를 덮지 않는다.
- 오른쪽 패널의 좁은/넓은 전환을 공통화했다. 창 크기 변경 시 특정 패널만 다른 여백 전환을 하지 않는다.
- 작업 기록은 먼저 현재 캐시를 표시한다. 스토리 응답을 기다리는 동안 목록을 숨기지 않는다. AiTaskStore.Changes는 최초 최신 스냅샷 이후 관측 ID의 변경분만 읽는다. 원본 로그와 전체 조회 기능은 유지한다.
- 반복 작업 목록은 백그라운드에서 읽고 보이는 동안만 조회한다. 작업 카드 타이머도 보이는 실행 카드에서만 작동한다.
- 캐릭터 요약 읽기와 Codex 실행 파일 탐색을 UI 스레드에서 분리했다. 업적 템플릿을 한 번 만들고 필터/테마 갱신을 묶어 처리하며 선택을 보존한다.
- 대화 복원 응답에 선택 세대를 적용했다. 다른 메뉴로 이동한 뒤 늦은 응답이 현재 화면을 덮지 않는다. 과거 메시지마다 수행하던 끝 스크롤은 복원 마지막 한 번으로 줄였다.
- 캘린더 자동 갱신은 열린 날짜만 갱신하며 일정 편집이나 닫힌 상세를 덮지 않는다.
- 스토리 화면과 상세는 같은 상태 조회를 공유한다. 업적의 사용하지 않는 DetailPanel 의존성과 제거한 탭의 도우미를 삭제했다.

## 실제 화면 및 회귀 검증

- 설치본에서 일상 → 작업 기록 → 일상 → 스토리 → 실행 상세, 캐릭터 → 업적, 일반 설정 → 설치 관리 전환을 확인했다.
- 업적 미확인 필터가 패널을 닫지 않고 적용되는 것과 선택 상세 및 공략 버튼을 확인했다.
- 설치 관리 전체 스크롤 끝과 후타오 카드 전체를 확인했다. 작업 버튼이 카드를 가리지 않는다.
- 같은 깊이의 오른쪽 패널 쌍 전체 전환, 같은 경로 콘텐츠 교체, 캘린더 갱신 중 편집/닫힘 보존을 무입력 자체 검사에 포함했다.

## 측정 범위

전체 앱의 탐색, 표시, 조회 경로와 의존성을 대상으로 수정했으며 게임 기능을 삭제하거나 폴링 간격을 임의로 늘리지 않았다. 새 런타임 의존성은 없다. 실제 게임 플레이 완료나 장시간 부하 시험을 했다는 의미는 아니다. Markdown 전체 구문 분석은 참조 링크의 의미를 보존하기 위해 유지하고, 과거 채팅 본문은 현재 방식대로 복원한다. 모든 대화 길이에서 일정한 메모리를 사용한다고 주장하지 않는다.


## 추가 점검 — 2026-10-01

기존 표시·버튼·작업 실행 의미는 유지했다. 같은 그림과 결과를 반복 해석하던 비용, 변화 없는 작업 목록 갱신, 단일 작업 검색과 Markdown 초기 문단 접근을 줄였다.

- `BitmapCache`: 동시 요청을 합치고 동결한 이미지를 공유한다. 최대 128개/16 MiB이며 디코딩된 이미지와 보존한 원본 스트림의 비용도 계산한다. 큰 항목은 캐시하지 않고, 실패 항목은 다음 요청에서 재시도한다. 기존 로컬 디스크 캐시와 출처 검증은 유지한다.
- `AiTaskRecord.Result`: 대입할 때 한 번 정규화한다. 진행률/카드/화면이 같은 결과를 읽고, 편집 화면은 필요한 자료를 복제한 뒤 수정한다.
- 작업 목록: 변경된 작업만 갱신하고, 변화가 없으면 목록 정렬과 카드 투영을 반복하지 않는다. 시간 표시와 실제 실행 중 조회는 유지한다.
- SQLite: 최신 작업 ID 검색에 재생성 가능한 부분 인덱스를 둔다. 사용자 기록의 형식은 바꾸지 않는다.
- Markdown: 첫 표시 때 WPF 문단 목록을 한 번 모아 사용한다. 스트리밍 방식은 유지한다.

### 합성 측정

네트워크와 실제 게임 입력 없이 300개 작업/3,000개 이력/16 KB 결과 참조/300개 문단/같은 그림 100개 표시를 사용했다. 같은 기준으로 세 번 측정한 중앙값이며 전체 앱 시작 시간이나 실제 게임 성능을 뜻하지 않는다. 재측정은 `apps/desktop/benchmark.ps1`, 비교 결과는 `apps/desktop/benchmark/comparison.json`에 있다.

| 작업당 시간 | 변경 전 | 변경 후 |
|---|---:|---:|
| 작업 ID 조회 | 11.97 ms | 1.76 ms |
| 변화 없는 목록 갱신 | 28.01 ms | 0.0153 ms |
| Markdown 첫 표시 | 79.52 ms | 23.87 ms |
| 진행률 투영 | 0.431 ms | 0.000659 ms |
| 같은 그림 100개의 고유 BitmapSource 수 | 100 | 1 |

Markdown 스트리밍 갱신은 약 1.04 ms로 유지됐다. 진행률 수치는 전체 화면 지연이 아닌 작은 연산의 반복 측정이다.

### 용량과 공개 경계

2026-10-01 점검 시점, 무시되지 않은 공개 소스는 약 50.9 MiB, Git 객체는 약 40.3 MiB였다. 공개 파일 최대 크기는 OCR 모델 약 14.7 MiB이며 50 MiB 이상 파일은 없었다. OCR 모델·글꼴·브랜딩이 주된 소스 용량이다.

개발 체크아웃 약 6.1 GiB 중 약 5.25 GiB는 무시된 반복 패키지 출력이었다. 설치 폴더 약 646 MiB에는 업데이트 백업 약 183 MiB와 번들 Python/스캐너 실행 환경이 포함됐다. 숫자는 점검 당시 값이며 후속 빌드와 백업에 따라 늘어난다. 백업과 이전 출력은 자동 삭제하지 않았다.

두 스캐너의 실행 대상이 x64인 것을 확인하고 패키징에서 사용하지 않는 x86 네이티브 파일을 제외했다. 다음 패키지의 비압축 파일 기준 약 68.1 MiB를 줄인다. 압축 설치 파일 감소량은 아직 측정하지 않았고, 기존 설치 폴더의 해당 파일을 삭제한 것은 아니다.

현재 소스 공개 경계 검사와 도달 가능한 과거 텍스트 버전 818개에 대한 자격증명/개인 자료 패턴 검사에서 의심 항목은 없었다. 패턴 검사 통과는 모든 보안 문제나 모든 이미지의 재배포 권리 검토를 완료했다는 뜻은 아니다. 게임 이미지의 라이선스 범위는 별도로 확인한다. 실행 환경·설치 파일·개인 자료는 소스 Git에 넣지 않는다.

### 종료와 유지보수

자동 화면 검사에서 실제 AI app-server가 늦게 시작해 임시 `ai-workspace` 삭제와 겹치는 경합을 수정했다. 가짜 검사 창에서는 AI 연결을 시작하지 않고, 실행 파일 탐색 중 객체가 종료되면 뒤늦게 프로세스를 만들지 않는다. 종료 시 프로세스가 끝나는 것을 기다린다. 운영 화면의 정상 AI 연결은 유지한다.

공통 오류 기록과 개인정보 없는 공유 보고서는 [지원용 진단 기록](SUPPORT-DIAGNOSTICS.ko.md)을 따른다. 자체 검사, 캐시/인덱스/진행률 회귀 검사, 진단의 개인정보·용량·종료 검사 및 공개 소스 검사를 통과했다.


사용자 자료 폴더도 별도로 확인했다. 약 5.90 GiB 중 외부 구성요소가 3.59 GiB, 마이그레이션 백업이 1.62 GiB였다. 캐릭터 그림의 디스크 캐시는 약 41.2 MiB다. 스캐너 구성요소는 여러 구형 버전과 실패한 다운로드 stage를 포함해 약 1.40 GiB이며, 별도 구성요소 다운로드 보관분도 약 551 MiB가 쌓여 있다. 이 용량은 공개 Git 소스에 포함되지 않는다. 구형 스캐너 폴더에는 사용자 설정과 내보내기가 있을 수 있어, 개발 출력·다운로드·복구 백업과 개인 자료를 구분하지 않고 삭제하지 않았다. 실제 설치 파일만 줄인다고 기존 사용자 자료가 함께 줄어들지는 않는다.


### 추가 정리와 최종 검증

2026-10-01 후속 사용자 요청으로 실제 정리를 실행했다. 반복 패키지 15개에서 5,102,630,148바이트, 리디렉션되지 않은 실제 저장소에서 비활성 프로그램·검증된 다운로드·실패한 설치 ZIP·이전 앱 파일 백업 598개에서 1,467,291,528바이트를 삭제했다. 두 검증된 결과만 합쳐 약 6.12 GiB다. 공식 스캐너와 현재 구성요소, 사용자 설정·스캔 내보내기·마이그레이션 백업은 보존했다. 삭제 대상 잔존 파일 0개와 실제 개인 기록 297개의 해시 일치를 확인했다. 이전 별도 기록도 첫 정리에서 8,519개를 비교해 변화가 없었다.

성능 통합 `765a26d`와 후속 필터/사용 안내까지 포함한 `135fc46` 소스를 격리 체크아웃에서 x64 Windows GUI 실행 파일로 빌드했다. 전체 자체 검사 exit 0과 설치된 공개 파일 77개의 SHA-256 일치, 정상 재시작 뒤 실제 창의 응답을 확인했다. 실행 파일 SHA-256은 `d8757633d9741ecb2e7c47d3312f6aabd072eef77f8751ee66f94240fdae76cf`다. 설치 사전 점검의 활성 AI 작업·제어/스캔 worker는 0이었고 입력 잠금도 비어 있었다. 게임과 언락커는 종료하지 않았다.

실제 일반 데스크톱 경로에서 잰 실행 파일·공개 자료·필수 도구 합계는 377,131,772바이트(약 359.7 MiB)이며 복구 백업은 별도다. 단순 복사 시 실행 파일이 잠겨 중단된 첫 시도에서는 앱 파일이 교체되지 않았다. 정상 창 종료 및 종료 뒤 예약 에이전트 중단을 확인한 뒤 교체를 완료했고, 직전 설치 파일의 복구 백업을 유지했다. 로컬 Conventional Commits로 통합했으며 원격 업로드는 하지 않았다.
