# Catheryne 제품 흐름과 지식 배포 설계

> 2026-09-26 후속 기준: [목표 완수와 오늘 할 일](GOAL-ORCHESTRATION.ko.md). 목표·일과·메뉴 관련 충돌은 후속 기준을 따른다. 아래 이전 시점의 경로/미이전 상태는 역사적 설명이며 현재 개발 원본은 통합 저장소다.
2026-09-26. 설계 확정안. 이 문서는 기존 개발용 파일 선택 화면을 최종 사용자 흐름으로 간주하지 않는다. 이번에는 UI/서버를 변경하지 않았다.

## 제품의 중심

사용자가 목표를 선택하거나 AI에게 말한다 → 동일한 GoalRequest 생성 → 조건 확인 → 실행 계획 → 로컬 실행 → 근거 검증 → 개인 기록 갱신. UI와 AI는 서로 다른 기능 경로가 아니라 같은 목표 시스템의 두 진입점이다.

## 화면 정보 구조

최상단 앱 아이콘은 홈. 사이드바: 화면·성능 / 스토리 / 캐릭터 / 업적. 하단 설정.

- 홈: 목표 입력·최근 작업·현재 작업으로 복귀. 어디서 만든 목표든 동일한 전역 작업 카드로 표시.
- 화면·성능: FPS·해상도·화면 모드·HDR·실행 성능. 언락커는 구현 공급자다. DLL은 고급 영역. 실행 경로·채널은 설정.
- 스토리: 검색·지역/임무 종류·완료/미완료/확인 필요·선행 조건·지원 수준·목표 선택. 임무 JSON은 기본 UX에서 제거 예정.
- 캐릭터: 보유·장착·추천과 장착 목표 생성. 추천과 보유 사실 구분.
- 업적: 현황·조건·수집·달성 목표. 아직 자동 수행할 수 없는 항목은 실행 가능한 것으로 표시하지 않음.
- 설정: 설치·채널·AI 연결·데이터·알림·앱 동작.

실행 전에는 목표/조건/주요 정책과 시작 버튼, 실행 중에는 행동/검증된 진행/시간 및 일시중지·직접 조작·종료. 개발용 관제 생명주기는 앱이 관리하며 기본 UI에 노출하지 않는 것이 목표다. AI에 맡기는 버튼은 연결된 AI의 실행 능력이 확인된 경우에만 동작한다. MCP 연결 자체가 AI 대화를 시작해주지는 않는다.

## 세 가지 데이터 책임

1. 공유 지식: 임무·업적·캐릭터 식별, 선행 조건, 공략 요약, 장비 추천 조건, 검증된 수행 절차. 공개 가능한 출처와 라이선스만.
2. 개인 상태: 보유 무기·성유물, 장착 관계, 완료 업적, 임무 관측, 목표와 행동 기록. 사용자 PC가 기본 원본. 중앙 서버에 자동 업로드하지 않는다.
3. 실행 상태: 현재 목표·계획 버전·관측·조작권·중단 상태. 로컬 정규 실행 관리자가 소유. 원격 콘텐츠 서버가 게임 입력을 결정하거나 권한을 부여하지 않는다.

공유 지식이 최신이어도 개인 진행은 미확인일 수 있다. 카탈로그에 존재하는 임무와 자동 실행 검증을 마친 임무는 별개의 상태다. 전체 목록의 완료 여부를 게임에서 일괄 읽을 수 있다고 전제하지 않는다.

## 공통 모델

- CatalogEntity: 안정적인 ID, 표시 이름/언어, 게임 버전, 출처, 검토 상태. 이름을 기본키로 쓰지 않음.
- Quest/Achievement: 선행 조건, 분기, 목표/성공 조건, 관련 캐릭터/지역, 선택적 공략 연결.
- BuildRecommendation: 캐릭터/역할/파티 가정, 무기·성유물 후보, 주요 옵션, 목표 능력치, 출처와 검증 버전. 단일 추천 순위를 모든 상황에 적용하지 않음.
- Playbook: 지원 게임 버전·능력 요구, 단계별 관측/실행/완료/복구. 고정 좌표 매크로를 콘텐츠로 배포하지 않음.
- GoalRequest: 종류, 대상 ID 또는 자유 입력 목표, 프로필 ID, 사용자 정책.
- TaskPlan: 카탈로그 릴리스/개인 스냅샷/실행 절차 버전에 고정된 계획. AI가 제안하고 로컬 검증기가 승인된 도구·조건을 검사.

화면 검색·MCP 질의·추천 화면이 같은 카탈로그를 사용한다. 캐시/검색 인덱스는 재생성 가능. 현재 별개인 ProfileStore/GOOD 관리와 계획 입력은 공통 모델로 수렴시켜야 하며 새 중복 데이터베이스를 추가하지 않는다.

## 서버와 배포

현재 core-api는 Express/PostgreSQL 기반의 랭킹·리뷰·제안 서비스다. 연결 인프라는 활용 가능하지만 현재 코드는 범용 원신 지식 서비스가 아니다. 실제 운영 상태·관리 권한·배포 경로는 미검증.

권장: 콘텐츠 작성/검토는 서버에서, 사용은 버전 고정된 다운로드 카탈로그로 로컬에서. 초기에는 JSON 릴리스 묶음과 manifest로 충분하며, 클라이언트마다 DB 서버를 요구하지 않는다. 필요 시 로컬 SQLite 검색 인덱스 추가. 원격 PostgreSQL은 파이프라인 관리·중복 검토·릴리스 추적 용도다.

core-api를 활용할 때는 catheryne 스키마와 /catheryne/v1 경로로 도메인을 분리하고 기존 랭킹·관리자 로그인 흐름에 결합하지 않는다. 공개 카탈로그 읽기는 회원가입 불필요, 쓰기/발행은 별도 관리 권한. 기존 서비스 무중단 마이그레이션과 권한 점검 후 배포한다. 이번 설계는 서버 변경·배포 승인이 아니다.

클라이언트: 내장 최소 카탈로그 → 릴리스 확인 → 변경 묶음 수신 → 스키마/참조/해시 및 신뢰할 수 있는 배포 서명 검증 → 원자적 활성화. 실패 시 이전 릴리스 유지. 해시는 손상 검사용이며 그 자체로 배포자 인증을 대체하지 않는다. 진행 중 작업은 사용 중인 릴리스에 고정하고 새 자료는 다음 작업부터 적용한다. 네트워크가 끊겨도 이미 받은 자료·조회·실행을 사용할 수 있다.

## 갱신 파이프라인

허용된 출처 수집 → 원본 출처/버전 기록 → 차이 검출 → 정규화 → ID/선행조건/순환/게임버전 검증 → 추천 조건 및 수행 절차 검토 → 릴리스 후보 → 회귀 테스트 → 발행.

LLM 추출 결과는 초안이다. 공략 문장에 있는 지시를 실행 권한으로 취급하지 않는다. 코드·임의 셸 명령을 카탈로그 데이터로 받아 실행하지 않는다. 행동은 로컬에서 허용한 도구 스키마만 사용한다.

수행 지원 수준: 정보 제공 / AI 보조 가능 / 검증된 자동 수행 / 점검 필요. 새 패치의 새 콘텐츠를 일괄 자동 수행 가능으로 승격하지 않는다. 출처의 이용·재배포 권한 없는 엑셀은 서버에 재배포하지 않으며, 링크 안내 또는 사용자가 가져온 로컬 자료로 처리한다. '이 정도면 잘 키웠다' 원본과 권한은 아직 확인 전이다.

## 사용자 시작 흐름

설치 → 게임 탐지 → 사용할 AI 연결(지원 가능한 호스트만) → 선택적으로 계정 수집 → 목표 선택/대화 요청 → 선행 조건/수행 가능 범위 확인 → 실행. 계정 수집을 모든 기능의 강제 선행 조건으로 만들지 않는다. AI 미연결 상태에서 가능한 설정·조회·스캔과 AI가 필요한 수행을 명확히 구분한다.

스토리 선택과 AI 자연어 요청은 모두 같은 GoalRequest로 변환한다. 사용자에게 계획 JSON을 만들게 하지 않는다. 계획이 없거나 자동 수행 검증이 없는 경우 지원 범위를 알리고, 가능한 현장 관측·AI 보조 경로를 사용한다.

## 도입 순서와 완료 기준

1. 화면·기능 정보 구조와 공통 UI 컴포넌트 확정. 기존 컨트롤 동작 보존.
2. 카탈로그 스키마·로컬 로더·출처/지원 수준을 갖춘 작은 실제 콘텐츠 묶음. 별도 DB 서버 없이 동작.
3. UI 선택/MCP 목표 요청이 같은 GoalRequest를 만들고 작업 카드·실행 관리자까지 연결되는 한 가지 종단 흐름 검증.
4. 개인 진행과 보유 데이터 연결, 추천의 조건/근거 표시. 알 수 없는 완료 상태는 미확인 유지.
5. 검증 범위를 넓히고 갱신 파이프라인 구축. 서버가 필요한 시점에 core-api 도메인 추가.

합격 기준: 사용자가 파일 경로·JSON·관제 프로세스를 알 필요 없음; 동일 목표의 UI/MCP 결과 일치; 인터넷 단절 시 기존 카탈로그 사용; 실패 업데이트에서 이전 버전 유지; 실행 중 버전 변경 없음; 개인정보 자동 전송 없음; 미지원 작업 실행 차단; 실제 목표 완료를 관측으로 검증.

## AI 중심 UI 뼈대 (2026-09-27)
구현: WorkspaceHome 단일 홈/탐색 화면. AI, 목표, 자료, 도구 메뉴. 기존 페이지는 기존 경로로 연결하며 저장/스캐너/관제 엔진을 복제하지 않는다. 자료는 캐릭터·장비/업적, 도구는 화면·성능/기존 스토리 관제/일상으로 연결한다. 링크·설정·게임 시작 유지.
AI 홈은 공식 Codex App Server로 ChatGPT 계정 연결, 메시지/첨부 전송, 응답 스트리밍과 중단, 대화 목록과 재개를 제공한다. 대화는 전용 로컬 작업 공간에 속하며 ChatGPT 웹 프로젝트가 아니다.
구현: Catheryne 도구 연결, 대화별 작업 카드, 대화 밖 상단 실행 현황, 실제 모델/사용량 선택과 조회. 남은 구현: 내장 Computer Use 연결과 자율 게임 수행 계획. 기존 관제는 전환 기간 동안 도구에 남긴다. 목표 등록이 AI 실행을 의미하지 않는다.
