# 원석 명세서

`내 계정 → 원석 명세서`에서 현재 버전의 전체 수입/예상 총량을 먼저 본다. 항목별 보기를 펼치면 원석 예상량이 많은 순서로 색상이 다른 막대를 표시한다. 업적·일별 수입·집계 기준·직접 기록은 접힌 상세에 둔다.

## 서로 다른 네 가지 기록

- **버전 명세서 참고:** [Genshin Bookkeeping](https://docs.google.com/spreadsheets/d/1l9HPu2cAzTckdXtr7u-7D8NSKzZNUqOuvbmxERFZ_6w/edit)의 버전별 시트에서 **Primogems 열만** 읽는다. 이벤트·상시 콘텐츠·웹/이메일·일일 의뢰·상시 도전·무료 기행으로 묶고 Total F2P와 합계를 대조한다. 인연 열, 유료 기행, 공월, 아래쪽 환산 중복 행은 제외한다. `est.` 여부를 보존하며 정규화된 참고값이지 정확한 개인 수령 대상 목록이 아니다. 원본을 앱에 재배포하지 않고 공개 CSV를 로컬 캐시에 조회한다. 열이 바뀌면 기존 캐시를 유지한다.
- **버전별 업적:** 기존 Paimon.moe 카탈로그의 `reward`와 `ver`를 공통 `AchievementRow`에 추가했다. 기존 스캔의 확인 상태를 그대로 사용한다. 로컬 기본 프로필은 HoYoLAB UID와 자동 연결된 자료가 아니며, 달성 보상은 수령한 원석이나 획득 시각을 증명하지 않는다. 보상량 미상은 0으로 채우지 않는다.
- **기간 수입:** 상단 공통 계정 관리에서 선택한 HoYoLAB UID/서버로 여행자 일기를 읽는다. 날짜 선택 없이 현재 버전을 고른다. [공식 인게임 공지 아카이브](https://github.com/KQM-git/GINews)의 업데이트 점검 시작 시각(UTC+8)부터 다음 버전 시작 전까지 집계한다. 다음 시작일이 없으면 명세서의 일수로 종료일을 예상하며 현재 시각 이후의 수입은 집계하지 않는다. 검증된 시작일은 catalog/versions.json에 출처와 함께 두고 최신 공지를 매일 갱신한다. 확인하지 못한 과거 버전의 기간은 미확인으로 남긴다. 일기는 원석만 집계하며 다른 버전 콘텐츠에서 얻은 원석도 포함할 수 있다.
- **직접 기록한 보상:** 선택된 HoYoLAB 계정과 버전별로 항목, 재화, 전체 수량, 받은 수량을 기록한다. 받은 수량을 비우면 미확인이다. 수령량을 아는 항목에서만 남은 양을 계산하고 미확인 항목 수를 별도로 표시한다. 원석·뒤얽힌 인연·만남의 인연·창세의 결정은 각각 합산한다.

항목 수입은 일기의 분류 이름으로 묶는다. ID는 의미가 변할 수 있어 사용하지 않으며, 모르는 분류는 총량 미확인인 기타 수입으로 보존한다.

이 네 숫자를 서로 더하거나 `명세서 - 기간 수입`으로 전체 잔여 보상을 계산하지 않는다. 리딤코드 등록, 캘린더 완료를 수령 증거로 바꾸지 않는다. 상자·임무 전체의 개인 미수령 목록은 제공하지 않는다.

## 일기 저장과 갱신

[genshin.py의 일기 프로토콜](https://github.com/seriaati/genshin.py/blob/master/genshin/client/components/diary.py)과 [모델](https://github.com/seriaati/genshin.py/blob/master/genshin/models/genshin/diary.py)을 확인해, 기존 C# HoYoLAB 클라이언트로 공식 `sg-hk4e-api.hoyolab.com/event/ysledgeros/month_info` 및 `month_detail`을 호출한다. 새 로그인 방식이나 Python 의존성을 추가하지 않는다.

- 앱 또는 기존 일상 백그라운드가 실행 중이고 HoYoLAB이 연결되어 있으면 6시간마다 최근 3개 달을 조회한다. 앱의 기존 백그라운드 실행 설정을 따른다. 프로그램이 꺼져 있는 동안은 조회하지 않는다.
- 상세 페이지를 끝까지 읽고 월 합계, 응답 UID/서버/월, 상세 연도, 조회 전후 합계와 첫 페이지를 대조한다. 페이지 한도·실패·자료 변경 시 해당 달을 저장하지 않는다. 다음 조회 또는 새로고침으로 재시도한다.
- 상세 항목에는 거래 고유 ID가 없다. 같은 시각·분류·금액의 여러 보상을 보존한다. **검증된 월 스냅샷 전체**가 조회의 원본이며, 재조회 결과를 누적 추가하지 않는다.
- 월 스냅샷과 수령 기록은 기존 로컬 DB에 `server:uid`로 분리한다. 연도도 월 키에 포함한다. 조회 가능 기간이 지나도 저장한 달을 지우지 않는다.
- 미수집 달, 조회 실패, 관측 시각을 표시한다. 저장된 일기 합계는 HoYoLAB에 반영된 범위의 값이며, 최신 플레이 직후의 완전한 수입을 보장하지 않는다.
- 인증정보는 기존 Windows 사용자 암호화 저장소를 재사용한다. 공개 명세서/업적 요청에는 인증정보를 전달하지 않는다.

## 공통 조회

`catheryne_query(section="primogems", query="7.1", offset=0)`은 같은 서비스에서 버전 기간을 자동 적용한다. 빈 query는 현재 버전이다. 고급 API의 `version|start|end` 날짜 지정은 호환을 유지한다. `primogems.refresh`는 공식 일기를 조회해 저장한다. 게임 조작이나 보상 수령을 수행하지 않는다.

## 검증

`--self-test`에 가짜 자료 기반 테스트를 포함한다. 동일 시각 복수 수입, 재조회 중복 방지, 월/연도/계정 경계, 페이지 종료와 변경 감지, 불완전 조회 시 이전 기록 보존, 날짜 포함 범위, 공개 표 형식 변경, 업적 보상 미상, 부분 수령과 삭제, 계정 전환, 화면 경로를 검사한다. 실제 공개 명세서 응답과 좁은/넓은 화면도 별도로 확인한다. 2026-09-29에는 기존 HoYoLAB 연결로 최근 3개 달의 공식 일기 조회와 이번 달 로컬 보관까지 확인했다. 다른 계정의 인증 만료·조회 제한은 연결 상태에 따라 달라질 수 있다.
