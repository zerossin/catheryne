# 공통 UX 원칙

사용자가 내부 구현이나 파일 경로를 몰라도 현재 상태와 다음 행동을 이해할 수 있어야 한다.

앱의 라벨·도움말·상태·오류·기본 입력값·AI 질문 템플릿은 Locale을 사용한다. 조건부 문구와 숫자가 들어가는 문장은 완전한 번역 단위로 관리한다. 원소·무기·성유물·재료 이름은 동일한 공개 게임 목록에서 표시 언어로 조회하며, 저장된 식별자나 원본 자료를 번역하지 않는다. 직접 작성한 목표·이름·메모와 외부 공략 원문은 보존한다. 앱이 제공한 기본 목표는 표시만 번역하고 편집하지 않은 저장값을 유지한다.

`scripts/check-localization.py`로 조건부 라벨·옵션·서식 지정자와 번역을 거치지 않는 UI 문구를 검사한다. `--self-test` 및 `--self-test --english`는 각각 격리된 가짜 설정으로 전체 검증을 실행한다. 영어로 검사할 때 한국어 문자열을 고정한 테스트 기대값을 사용하지 않는다.

- 첫 화면은 결과 중심: 진행도 → 분류 → 항목 → 항목의 조건/공략. 같은 요약을 복제한 상세 화면은 만들지 않는다.
- 왼쪽은 기본 메뉴와 하위 탐색, 오른쪽은 선택한 기능의 검색·목록·선택 항목 정보. 업적 공략을 별도 탭으로 분리하지 않는다.
- 동작은 목적별 카드에 묶는다. 주 동작은 한 줄, 보조 동작은 같은 너비의 행. 버튼 간 가로 최소 8px, 세로 최소 8px, 그룹 간 12px 이상.
- 같은 의미에는 같은 용어: 스캐너 실행 / 결과 불러오기 / 결과 내보내기. 읽기 갱신은 새로고침. 실제 저장 작업에만 저장을 사용한다.
- 다른 의미를 가진 중지/종료/조작권 이전은 이름 통일을 이유로 합치지 않는다.
- 공통 PanelUi를 먼저 수정한다. 화면별 임의 높이/여백/복제 버튼 구현은 피한다.
- 경로·진단 정보는 접힌 관리 영역에 둔다. 사용자가 판단할 필요 없는 DB/스키마 설명은 본문에서 제외한다.
- 확인 완료/검증 대기/미확인을 구분한다. 미확인을 미달성으로 단정하지 않는다. 개별 진행률은 카탈로그 분모와 확인된 ID 교집합으로 산출한다. 전체 달성 막대는 HoYoLAB 총 달성 수(없으면 개별 확인 수)와 공개 업적 목록 개수로 표시하며, 공식 총수가 목록보다 많으면 백분율을 만들지 않는다. 총 달성 수만으로 개별 업적의 완료를 추정하지 않는다.
- 공략은 AI의 참조 데이터다. 출처와 확인 상태는 기계용 문맥에 보존하고, 사용자 화면에 공략 설명·출처 푸터·내부 ID를 상시 노출하지 않는다.
- 목록은 가상화하고, 화면 크기에 맞춰 늘인다. 화면 검증은 긴 제목·스크롤·필터·빈 결과·선택 상태를 포함한다.

2026-09-27 적용: 업적 현황/테마/목록/조건/공략 연결, 캐릭터·업적 수집 관리 용어 및 그룹, 공통 버튼과 작업 행 간격.

## 확정된 하단 작업 행과 저장 규칙

스토리와 최신화의 파일 관리는 PanelUi.FooterActions를 공유한다. 높이 40px, 간격 8px.
스토리는 시작/종료 1:1, 최신화의 파일 관리는 결과 불러오기/결과 내보내기 1:1. 최신화 시작·중단은 선택 범위 아래에 두고 목록 탭에는 중복 작업 행을 두지 않는다.
수집 관리의 대형 고정 카드 및 접기 영역 제안은 폐기한다.

일반 설정은 자동 저장한다. 텍스트 입력은 450ms 지연 후 유효성 검사하여 저장하고, 미완성/잘못된 값은 마지막 유효값을 유지한다.
화면/런처/레진/스토리 설정에 별도 저장 버튼이나 자동 저장 설명을 덧붙이지 않는다.
스토리 수행 방식은 관제 연결 중 변경 즉시 configure 경로로 적용한다. 연결 전에는 해당 편집을 비활성화한다.
내 프리셋 저장, 파일 내보내기, 실행/중지처럼 명시적 결과를 만드는 동작만 버튼으로 남긴다.
저장 시점과 게임 적용 시점은 구분한다. 이미 실행된 게임의 설정을 자동으로 변경하지 않는다.

- 자명한 사용법 설명을 본문에 추가하지 않는다. 여백을 설명으로 채우지 않는다. 제목·본문·상태는 타이포그래피와 영역으로 구분하며 업적의 빈 상세 영역은 표면을 유지하고 내용만 비운다. 상태 수치는 필터에 모으고 0건을 본문에 나열하지 않는다.

## 점진적 정보 공개와 화면 점검

보조 정보를 삭제하지 말고 ? 도움말/접힌 상세에 보존한다. 상태 집계·미확인의 의미·출처·적용 조건을 필요할 때 찾을 수 있어야 한다.
사용자가 바로 판단해야 하는 오류·실행 상태·미지원 상태는 숨기지 않는다.
2026-09-27 점검: 업적 집계 → 진행도 ?, 공통 메뉴 소개 → 제목 ?, 목표/레진 한도/모드 설명 → 카드 ?, 구성요소 역할 → 카드 ?, 화면 소개/HDR → 도움말. 스토리 실패 정책과 레진 인증 설명은 기존 도움말/접기 유지. 실행 오류와 계획 미지원 표시는 본문 유지.
모든 스크롤은 실제 넘침이 있을 때만 그린다. 스크롤 여백은 보존하여 내용 너비가 흔들리지 않게 한다.
창 기본값 1240×760 DIP, 현재 작업 영역보다 작게 제한. 사각 표면의 모서리는 PanelUi.SurfaceRadius의 8 DIP로 통일한다. WPF 크롬과 Windows 둥근 창도 같은 기준을 사용한다. 원형 아이콘·스위치·알약은 해당 도형을 유지한다.

새 UI/기능 작성 전에 기존 동등 역할과 공통 구현을 검색한다. 공통 구현 확장 → 모든 호출부 적용 → 예외 검색 순서로 검증한다. 제목과 도움말은 PanelUi.Heading을 공유하며 도움말은 대상 바로 옆에 둔다.

## 창과 반응형 배치

창 조작은 WindowChrome과 LauncherWindowLayout이 담당한다. 기본 1240×760, 최소 780×600 DIP이며 최대화는 모니터 작업 영역을 사용한다. 창 크기·위치·최대화 상태는 공개 소스 밖 개인 설정에 저장한다. 1180 DIP 미만에서는 공통 기능 패널을 한 화면으로 펼친다. 닫기로 상위 메뉴를 다시 표시하며 뒤로가기 버튼은 두지 않는다. 대화 목록은 좁은 창에서 채팅을 압축하지 않고 겹쳐 열린다. 채팅 본문과 입력창은 최대 880 DIP를 유지한다. 닫기 호버만 빨간색이며 나머지 창 버튼은 중립색이다.

창 전환 애니메이션은 기본 Windows 창 스타일과 WindowChrome을 함께 사용하여 OS가 담당한다. 최대화 버튼만을 위한 별도 크기 애니메이션을 만들지 않는다. 단축키·스냅·복원도 같은 경로를 사용하며 Windows 애니메이션 접근성 설정을 존중한다. 상세 패널의 좁음/넓음 전환만 180ms로 보간한다.

진행 시간은 사용자 메시지 다음의 별도 줄에 표시하고 답변 본문과 구분한다. 생각 중·도구 실행 중 표시는 대화 영역에서 실제 진행 단계에 맞춰 빛나며 완료하면 빛남을 멈춘다. 입력창에는 응답 대기·응답 완료 문구를 두지 않는다.
