# HoYoLAB 계정 최신화

> 개발·통합 참고 문서입니다. 사용자 안내: [English](USER-GUIDE.md) · [한국어](USER-GUIDE.ko.md)

2026-09-29 적용.

- 자료의 **최신화 → HoYoLAB에서 최신화**가 기본 경로다. 기존 HoYoLAB 연결과 선택한 원신 계정을 사용한다. 게임 실행이나 조작은 필요 없다.
- **추가 수집**에서 기존 전체/선택 스캔과 중단·재개를 사용할 수 있다. 미장착 장비, 개별 업적 ID, API에 없는 돌파 단계 등은 이 경로로 보완한다.
- 연결 실패·권한 오류·불완전한 응답은 기존 스냅샷을 유지한다. 연결 버튼으로 다시 로그인할 수 있으며 스캔을 자동 시작하지 않는다.
- UI와 AI의 `account.refresh`는 같은 서비스와 ProfileStore를 사용한다. 최초 연결은 현재 로컬 기록에 선택한 UID/서버를 연결하고, 이후 다른 UID/서버는 병합하지 않는다.

## 자료의 의미

캐릭터 목록과 장착 무기·성유물 상세를 읽는다. 이 목록은 미장착 장비 전체를 포함하지 않는다. 무기·성유물 응답의 ID는 종류 번호이며 개별 소유 아이템 식별자로 쓰지 않는다.

장비 상태를 다중집합으로 대조하여 이동과 반복 조회를 처리한다. 기존 미장착 자료를 보존하며, 같은 종류의 장비와 정확히 대조하지 못한 관측은 `catheryne.pendingEquipment`에 남긴다. 보유 수에 새 물건으로 추가하지 않는다. 캐릭터 상세·육성 비교·AI 캐릭터 조회는 `AccountMerge.Equipped`라는 같은 조회 경로로 최신 장착 관측을 읽는다. 전체 스캔은 해당 장비 종류의 보류된 대조를 해소한다. 장착 위치를 더 이상 확정하지 못하는 기존 아이템은 null이며 미장착(빈 문자열)과 다르다.

특성은 고정한 genshin-db의 영문 이름과 운명의 자리 설명에서 확인한 보정만 적용한다. 확실하지 않은 특성은 추정하지 않고 기존 필드를 보존한다. 캐릭터 돌파 단계와 장비 잠금은 응답에 없으면 새 값으로 만들지 않는다. 여행자는 검증된 원소별 GOOD 키와 공통 Traveler 장비 위치를 사용한다.

업적 응답은 총 달성 수와 카테고리별 집계다. 개별 업적 완료나 보상 수령을 입증하지 않으므로 업적 ID 저장소·원석 수령액으로 변환하지 않는다. 집계는 최신화 화면에서 확인할 수 있다.

계정 원본은 `Catheryne.Account` 형식이며 캐릭터·장비에 게임 종류 ID(`gameId`)와 HoYoLAB의 이름을 보존한다. GOOD 키는 외부 도구 호환용 정보다. 숫자 매핑에 아직 없는 신캐릭터·신무기도 바로 목록과 현재 장착 정보에 반영한다. 한국어 이름은 필요할 때 공식 한국어 응답에서 받아 캐시하며 영문 응답으로 대체할 수 있다. 기존 GOOD 원본은 가져올 때 공통 모델로 변환하며 불변 스냅샷은 수정하지 않는다.

GOOD로 내보낼 때 미지원 키 또는 미지원 캐릭터 장착 위치를 가진 행은 `catheryne.nativeItems` 확장에 보존한다. 캣서린으로 다시 가져오면 복원되며, 확장을 읽지 않는 외부 도구에서는 해당 항목을 사용할 수 없다. 임의의 GOOD 키를 만들지 않는다. 새 GOOD 키가 확인되어도 게임 ID와 장착 연결을 유지한다. 특성의 기본 레벨 보정이 확인되지 않으면 HoYoLAB에 표시된 특성 이름·레벨을 제공하고 별자리 효과가 포함될 수 있음을 도움말로 알린다. 카탈로그 또는 계정 변환 규칙이 바뀌면 짧은 조회 캐시를 무효화한다.

## 출처와 갱신

- [genshin.py](https://github.com/seriaati/genshin.py): 공식 사이트의 내부 전적 API를 이용하는 MIT 라이선스 커뮤니티 래퍼. HoYoverse가 보증한 공개 개발자 SDK로 표현하지 않는다.
- 공식 HoYoLAB 전적의 `character/list`, `character/detail`, `achievement`를 읽는다. 전적 설정 변경·게임 입력·자동 CAPTCHA 처리는 하지 않는다.
- [Genshin Optimizer](https://github.com/frzyc/genshin-optimizer): 숫자 ID → GOOD 키, 여행자 원소/장비 위치.
- [genshin-db](https://github.com/theBowja/genshin-db): 특성 이름·운명의 자리 보정.

`apps/desktop/update-hoyo-catalog.py`가 기존 `catalog/game.json`과 같은 고정 커밋에서 `catalog/hoyolab.json`을 생성한다. 원본 리비전은 JSON의 `sources`, 라이선스는 기존 catalog/LICENSE 파일에 보존한다. 실행 중 계정 정보나 인증정보를 이 공개 데이터 저장소에 보내지 않는다. 계정 조회 쿠키는 기존 DPAPI 저장소에서 메모리로 읽어 공식 HoYoLAB 호스트에만 보낸다.

## 자동 최신화와 계정 관리 (2026-09-29)

- 상단 계정 메뉴에서 ChatGPT·HoYoLAB·리딤 계정을 관리한다. 출석·리딤·레진·달력·명세서의 명시적 동작은 공통 연결 확인/로그인을 사용한다. 각 화면에 별도 로그인 창이나 UID 선택기를 두지 않는다.
- `collection.refresh`의 `auto`는 HoYoLAB부터 조회한다. 같은 계정/현재 스냅샷의 1분 이내 확인은 재사용하고, 응답이 같으면 새 계정 스냅샷을 만들지 않는다. 다른 가져오기가 현재 원본을 바꾸면 캐시를 무효화한다.
- 연결을 거절한 경우에만 기존 증분 스캔 경로를 선택한다. API 오류를 거절로 취급하지 않는다. 게임 준비와 중단/재개는 기존 공통 실행 경로를 따른다.
- 전체/사용자 설정은 미장착 장비·개별 업적 등 추가 범위의 기존 수집 도구를 사용한다. HoYoLAB의 업적 합계를 개별 업적 완료로 바꾸지 않는다.


## 최신 관측과 표시 (2026-09-30)

- 캐릭터·무기·성유물 응답 전체를 각 행의 `hoyolab`에 보존한다. 지원하는 필드는 같은 계정 모델의 레벨·장착·세트 이름·이미지·실제 능력치로 투영한다. UI의 능력치 상세와 AI의 `finalStats`는 같은 값이며 장비에서 재계산한 수치가 아니다. 조건이 다른 추천표와의 판정은 자동 확정하지 않는다.
- 장착만 조회하여 개별 재고와 대응이 확정되지 않은 관측도 `AccountMerge.Inventory`로 목록·검색·필터·AI에 제공한다. `inventoryMatch:unresolved`는 보유 수 미확인 표시이며 확정 재고를 늘리지 않는다. 최신 장착 상태는 같은 관측에서 읽는다. 동일 상태의 동일 종류 무기는 종류 ID만으로 개체를 구별할 수 없지만 두 캐릭터의 현재 장착 결과와 관측된 최소 개수는 보존한다.
- 공식 응답의 이미지 URL을 우선 사용한다. 실패하거나 URL이 없으면 기존 고정 카탈로그를 시도한다. 새 항목의 이미지를 키 매핑에 의존시키지 않는다. 캐시는 임시 파일에 쓴 뒤 확정하여 동시에 표시되는 카드·상세가 덜 쓴 파일을 읽지 않게 한다.
- 성유물 종류 필터는 공식 세트 ID·한/영 이름 또는 검증된 GOOD 세트 이름을 사용한다. 부위와 주옵션 필터는 유지한다.

## 업적 테마 관측

- 공식 `achievement` 응답의 총 달성 개수와 테마별 ID·이름·달성 개수·달성률·표시 방식·이미지를 보관하고 업적 화면과 AI 조회에서 같은 응답을 사용한다. 개별 완료 ID 목록은 이 응답에 포함되지 않는다.
- 테마별 공식 달성률 100%를 개별 업적 완료 기록으로 바꾸지 않는다. 카탈로그에 아직 없는 공식 테마도 목록에 유지한다.
- 화면이 넓으면 테마·업적 목록·상세를 나란히 표시하고, 좁으면 같은 선택을 단계별로 표시한다. 총개수와 개별 확인 수가 다르면 달성 개수 옆 느낌표의 도움말에 차이를 표시한다.

확인한 공개 연동 구조: [gsuid_core 업적 자료](https://github.com/Genshin-bots/gsuid_core/blob/master/gsuid_core/utils/api/mys/models/achievement.py).
