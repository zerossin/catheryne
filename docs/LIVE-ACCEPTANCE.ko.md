# 실제 사용자 흐름 인수 테스트

2026-09-27. 사용자 요청의 전체 기획과 현재 코드 대조. **이 문서는 시험 계획이며 실행 결과가 아니다.** 과거 성공도 이번 설치본의 합격으로 이월하지 않는다. AI-ACCEPTANCE, AI-FUNCTION-PARITY, GOAL-ORCHESTRATION, EXTERNAL-TOOLS, SCANNING 및 실제 도구 카탈로그를 함께 대조했다. 오래된 문서의 미구현 문구가 최신 코드와 충돌하면 코드와 이번 실측을 우선한다.

## 상태와 합격의 뜻

- **구현**: 호출 경로가 존재한다. 실사용 합격을 뜻하지 않는다.
- **부분**: 일부 경로만 존재하거나 도구/자료/게임별 조건에 의존한다.
- **기획**: 전용 기능 또는 연결이 없다. 정확하게 미지원이라고 답해도 제품 기능 자체는 미완료다.
- 실행 결과는 미실행 / 통과 / 실패 / 조건 부족 / 미구현으로 별도 기록한다. 코드 구현 상태와 시험 결과를 섞지 않는다.
- AI 요청 → 실제 도구 → 실제 상태 변화 → 결과 재조회 → 원래 대화의 작업 카드/기록까지 확인한다. 버튼, 프로세스, 목표 등록만 확인하고 실행 완료로 판정하지 않는다.
- 일반 질문은 불필요한 작업을 만들지 않는다. 사람의 UI와 AI는 동일 설정·자료·작업 ID를 사용해야 한다.

## 짧은 시험 원칙

1. UI/조회/설정은 보통 30초~2분, 설치·짧은 수집은 2~5분, 게임 과제는 3~10분 한 건으로 제한한다. 시간은 상한 목표이지 완료율이 아니다.
2. 하나의 실제 완료 단위만 고른다. 메뉴 열고 닫기는 조작 연결의 합격이며 전투·스토리·파밍의 합격이 아니다. 짧은 스토리 단계, 단일 업적, 비경 1회는 해당 범위만 합격이다.
3. 장기 목표는 전체 수행하지 않는다. 수요 계산/계획/하위 작업 1회/잔여량 반영/재개까지 검증한다. 계산은 작은 합성 재고로 별도 확인하고, 실제 재고와 구분한다.
4. 10분 내 끝낼 수 없는 목표는 연결 및 하위 작업까지만 확인하고 **전체 완주 미검증**으로 남긴다. 무제한으로 진행하지 않는다.
5. 실제 레진 지출·보상 수령·설치 제거·계정 연결 해제 등은 시험 계획만으로 실행 승인을 얻은 것으로 해석하지 않는다. 실테스트 시작 시 허용 범위와 보존할 상태를 정한다. 원석·약한 레진·잠긴 장비 소비, 실제 뽑기는 기본 제외한다.
6. 요금 발생 시험은 모델/추론 수준을 명시한다. 단순 내부 도구 시험과 화면 판단 시험을 나누며 자동으로 비싼 모델로 올리지 않는다. 모델의 한 번 실패를 전체 모델 부적합으로 일반화하지 않는다.
7. 개인 스크린샷·UID·재고·대화·실행 결과는 공개 저장소 밖에 저장한다. 공개 문서에는 일반 시나리오만 둔다. 새 테스트 프레임워크나 중복 테스트 코드는 만들지 않는다.

## 순서와 결함 처리

1. A02~A04, C07, F09 화면 → B01~B05, C01~C02 무게임 기능 → A05~A10 AI 대화 → F01~F06 계정 서비스.
2. D03, D06~D07 게임 연결 → C03~C06 소범위 스캔 → E01~E03 외부 도구 → D04~D05/D08~D09 짧은 실제 완료.
3. D10~D11, E04/E07/E09, F07~F08은 구현 공백 목록으로 남기고 구현한 뒤 같은 계약으로 시험한다. 미지원 답변의 정직성과 기능 제공 여부는 따로 판정한다.
4. 실패하면 해당 경로에서 멈추고 원인→공통 구현 수정→동일 사례 재시험→이웃 기능 1건 확인. 전체 스캔·장기 파밍으로 되풀이하지 않는다.
5. 한 차례 예산은 20~30분 묶음. 각 사례의 상한 도달 시 중단/대기 상태를 기록하고 다음 독립 항목으로 넘어간다. 실제 게임 상황상 안전한 종료/일시정지를 먼저 확보한다.
