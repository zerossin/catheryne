# 수집 실행 계약

> 개발·통합 참고 문서입니다. 사용자 안내: [English](USER-GUIDE.md) · [한국어](USER-GUIDE.ko.md)

캐릭터·무기·성유물은 Inventory Kamera, 업적은 Akasha의 동일 엔진을 사용한다. `--catheryne-scan <job-directory>`는 별도 GUI를 생성하지 않는다. 런처 버튼과 AI는 ApplicationOperations → CollectionScanner로 실행한다.

작업별 디렉터리의 status.json은 원자적으로 교체하며 실제 관측 개수를 전달한다. stop 파일은 협력적 중단 요청이다. 입력 전·대기 중 중단, 게임 전경, 실행자 생존을 확인한다. 5초 안에 종료하지 않으면 작업 소유 프로세스만 종료한다. 동시 스캐너 실행은 단일 mutex로 막는다. 게임 AI 조작은 스캐너 실행 중 거부한다.

종료 코드 0, 상태 completed, 해당 작업의 result.json이 모두 있어야 ProfileStore로 가져온다. 실패·취소·OCR 오류 자료는 기존 계정을 덮어쓰지 않는다. 스캔 결과는 GOOD 또는 Akasha 양성 업적 자료로 정규화한다. 누락을 미보유로 취급하지 않는다.

Kamera는 영어 게임 언어와 16:9/16:10, HDR 끄기가 필요하다. 업적도 영어 게임 언어를 사용하며 업적 카테고리 검색창이 열린 화면에서 시작한다. 일반 실행에서는 게임 창이 표시되어야 하며, 분리 실행에서는 같은 수집기를 자식 세션에서 실행한다. 런처에만 시작·진행·중단을 표시한다. Kamera에는 해시를 검증한 공식 배포본의 인식 목록을 포함하며, 이후 갱신은 엔진의 공식 갱신 경로를 사용한다.

자동 검증은 게임 입력 없이 중단·실패·결과 저장 계약을 검사한다. 실제 게임 전체 스캔 성공과 별개다.


## 2026-09-27 이름 인식과 병합

- 계정 `catheryne.characterAliases`를 스캔 작업의 개인 names.json에 전달한다. 한국어 사용자 이름은 별도 한국어 OCR로 정확히 일치할 때만 매핑한다. 공개 기본값에 개인 별명을 넣지 않는다.
- GOOD 미지원 대상은 `catheryne.customCharacters`에 identity/alias/element/level/coverage를 저장한다. 별바다 인형과 미지원 여행자 원소를 다른 GOOD 캐릭터로 위장하지 않는다. 현재 확장 수집은 이름·원소·레벨이며 특성·무기는 확인된 기존 기록을 보존한다.
- 캐릭터는 key별 갱신, 생략된 수집 영역은 유지한다. 장비 OCR id는 스캔 순번이므로 병합 키로 쓰지 않는다. 성공한 무필터 전체 장비 스캔은 해당 영역을 교체하여 소모·강화도 반영한다.
- 범위가 불명확한 부분 장비는 동일 내용·수량을 대조하며 구분 불가능한 변경은 pendingEquipment로 보존한다. 자동으로 장비 개수를 늘리거나 다른 아이템을 덮어쓰지 않는다. 원본과 파생 스냅샷을 모두 보존한다.
- 같은 원본 재가져오기는 멱등이며 프로필별 프로세스 잠금으로 동시 갱신 손실을 방지한다.
- 한국어 이름 인식은 빌드 및 비입력 검증 단계다. 실제 게임 전체 재스캔 성공으로 간주하지 않는다.

상태와 체크포인트는 공통 원자적 저장 함수를 사용한다. 파일 공유 잠금이 잠깐 유지되면 제한된 시간 동안 교체를 재시도하고, 기존 스냅샷을 먼저 삭제하지 않는다. 런처의 JSON 읽기는 파일 교체를 허용한다. 중단 시 마지막 관측 개수를 유지하며 체크포인트에도 중단 상태를 기록한다.

## 확인 완료 업적의 증분 수집

런처는 같은 ProfileStore의 확인 완료 내보내기로 작업 폴더에 known-achievements.json을 만든다. Akasha의 기존 AchievementOverrides 경로로 전달하며 검증 대기 항목과 미수집 항목을 완료로 간주하지 않는다. 전체 업적 카탈로그로 검색어의 고유성을 판단하고, 모든 단계가 이미 확인된 검색만 건너뛴다.

체크포인트와 스캐너 자체 보관 파일에는 이전 확인 기록을 포함한다. 런처에 반환하는 result.json에는 이번 실행에서 새로 관측한 양성 기록만 담는다. 따라서 재사용한 기록의 원본, 검증 등급, 관측 시각을 새 스캔으로 덮지 않는다. 새 관측이 없는 정상 종료도 빈 양성 결과로 기존 자료를 보존한다.

최종 단계의 양성 판정은 별 개수와 화면의 Completed/Claim 표시를 함께 확인한다. 완료 문구를 읽지 못했거나 진행량만 표시된 경우에는 완료로 기록하지 않는다. 다단계 업적의 이전 단계는 별 개수를 유지한다. 새 관측은 기존 검증 대기 등급으로 저장하며, 게임 화면과 대조한 확정 자료만 확인 완료로 가져온다.

## 계정 수집 범위

내 계정 → 최신화의 사용자 설정과 AI scanner.start는 같은 AccountScanOptions를 사용한다. sections와 무기/성유물 최소 등급·레벨을 작업 options.json으로 전달한다. 생략 시 기존 전체 수집이다. 선택하지 않은 영역은 결과에서 생략하고 필터를 적용한 장비는 partial로 표시해 정규 병합기가 미관측 장비를 보존한다. 옵션은 이번 작업에만 적용하며 독립 Kamera 앱의 저장 설정을 바꾸지 않는다.

Kamera는 수집 전에 하루 한 번 기존 DatabaseManager로 인식 목록의 버전을 확인한다. 새 버전은 임시 폴더에서 모두 생성·검증한 뒤 반영한다. 네트워크 오류 시 기존 목록으로 시도하되 실제 인식 오류는 완료로 처리하지 않고 계정 자동 반영을 거부한다. 특정 무기명 예외는 추가하지 않는다.


## 2026-09-28 통합 최신화

내 계정 → 최신화가 수집·시작/중단·파일 가져오기/내보내기의 공통 진입점이다. 결과 목록 화면에는 중복 수집 설정과 작업 버튼을 두지 않는다. `scanner.start`는 auto/all/account/achievements를 동일 CollectionRefresh에서 실행한다. 자동 선택은 캐릭터/무기 7일, 성유물/재료/업적 1일 기준이며 변경 유무 판정은 아니다. 수집 범위는 직접 선택할 수 있다. 수집 설정 필터는 직접 선택일 때만 적용한다.

하나의 작업과 스캐너 잠금 안에서 영역별로 순차 실행하고, 성공한 영역을 ProfileStore로 반영한 뒤 완료 저널을 원자적으로 저장한다. `collection-refresh.json`은 영역별 마지막 성공한 전체 확인 시각의 원본이다. 부분 장비 수집으로 전체 신선도를 갱신하지 않는다. 기존 자료의 수집 시각이 불명확하면 최신으로 추정하지 않는다.

`scan-jobs/pending-refresh.json` 하나가 현재 이어갈 요청(범위/필터/원래 작업)을 가리킨다. UI와 AI 모두 같은 요청이면 완료 영역을 건너뛴다. 다른 요청은 새 작업이며 이전 결과와 저널은 보존한다. 오래 중단되어 갱신 기한이 지난 영역은 재확인한다. 중단 중이던 장비 영역은 목록을 다시 순회한다. 목록 순번은 아이템 ID가 아니다.

Kamera 7의 인식 캐시는 전처리된 화면 조각의 정확한 픽셀 해시, 크기, OCR 모드, 숫자 제한을 키로 사용한다. 높은 신뢰도의 비어 있지 않은 인식만 캐시한다. 최대 20,000개이며 영상은 저장하지 않는다. 엔진 버전별 데이터 폴더에 분리되고 손상/누락 시 재생성한다. 다음 수집도 화면을 순회하여 변화와 아이템 수를 확인하지만 동일 픽셀의 OCR은 재사용한다. 바뀐 아이템만 바로 찾아가는 기능으로 표현하면 안 된다. 작업 recognition.json에 실제 재사용/새 인식 수를 남긴다.

Akasha 9는 작업 폴더에 새 양성 관측만 checkpoint.json으로 저장한다. 중단/실패 때도 유효한 체크포인트를 검증 대기로 반영하고 같은 작업 재개 시 이용한다. 확인 완료 기록과 검증 대기의 등급은 합치지 않는다. 진입은 실화면에서 읽힌 메뉴 글자를 통해 시도하며 검색 화면을 확인하지 못하면 입력을 중단하고 같은 작업을 재개하도록 안내한다. 게임 입력 없이 검증한 테스트와 실게임 검증은 구분한다.
