# 분리 게임 실행 환경

## 단일 기준

게임 조작의 의미와 권한, 상태, 입력 소유권, 취소, 실행 결과는 기존 `GameTools`, `StoryClient`, `core/story-control`, `ExternalTools`, `CollectionRefresh`가 정의한다. 실행 환경은 이 구현들을 다른 Windows 세션에서 호출하는 전송 및 수명 경계다. 별도의 대화기, 이동기, 전투기, 스캐너 또는 작업 저장소를 만들지 않는다.

런처와 모델은 사용자 세션에 있고 게임, 입력 실행기, 관측, 보조 기능, BetterGI, 스캐너는 같은 Windows 자식 세션에 있어야 한다. 모든 세션은 같은 개인 데이터 루트를 사용한다. 자식 실행기는 검증된 환경을 계승하며 손실되거나 변경된 연결은 실패로 처리한다. 사용자 세션으로 자동 복귀하거나 중첩 자식 세션을 만들지 않는다.

## 직접 플레이와 자동화 시작

하단 게임 시작 버튼, Windows 바로 시작과 런처를 열 때의 게임 자동 시작은 사용자 데스크톱에서 직접 플레이하기 위한 실행이다. 자동화의 분리 실행 설정을 이 진입점에 적용하지 않는다. AI 시작과 스토리·수집 등 자동화 기능의 게임 실행 요청은 자동화 실행 설정을 따른다. 두 경우 모두 `LauncherOperations.Start`에 실행 목적을 명시하며 기존 설정 검증, 모드와 프레임 실행 및 소유 프로세스 관리는 같은 구현을 사용한다. 분리 실행의 인증 실패가 직접 플레이를 막지 않으며, 자동화 실패를 사용자 데스크톱 실행으로 바꾸지 않는다.
## 연결과 수명

`WindowsChildSession`은 Windows의 문서화된 WTS 및 RDP ActiveX API를 사용한다. 한 부모 세션의 한 자식 세션만 소유한다. 기존의 다른 자식 세션을 인수하지 않는다. 실행할 수 있는 파일은 현재 캣서린 실행 파일로 제한하며, 현재 사용자 토큰으로 지정 세션에 작업자를 실행하는 일회성 예약 작업은 실제 실행기 시작 응답을 확인한 뒤 제거한다. 연결 취소나 시작 실패에서는 해당 대기 인스턴스를 중단하고 등록도 제거한다. Windows 로그인은 사용자가 수행한다. 암호를 읽거나 저장하지 않으며 UAC, NLA, 인증서, Defender 설정을 낮추지 않는다.

`GameEnvironment`는 현재 사용자만 연결할 수 있는 임의 이름의 파이프를 사용한다. 프로세스 생성 시간, 실제 실행 파일 식별자, 실제 세션과 연결된 파이프의 서버 PID를 확인한다. 연결 소유자와 실행기의 파일 식별자는 시작 기록에 고정하며, 업데이트 중 실행 파일을 보존 이름으로 옮겨도 살아 있는 같은 프로세스를 계속 인정한다. 프로세스 생성 시간과 세션은 캐시와 관계없이 매번 확인하며 종료된 프로세스나 새 파일을 이전 소유자로 인정하지 않는다. `GameEnvironmentOperations`는 기존 도메인 진입점만 호출한다. GUI나 AI가 새 입력 경로를 구현하지 않는다. 종료는 해당 자식 세션의 기록된 작업에만 적용한다.

## 연결과 관제 UI

설정의 자동화 실행에서 분리 실행 또는 일반 실행을 선택한다. 연결, 게임 화면 보기, 직접 조작, 실행 환경 종료는 공통 설정 표면을 사용한다. 보기 전용 화면은 원격 입력을 받지 않는다. 직접 조작은 기존 관제의 조작권을 사용자에게 넘기고 위임 작업과 스캔이 입력을 해제한 뒤 허용한다. 자동 관제를 다시 선택하면 원격 화면을 숨기고 기존의 새 관측 게이트를 거친다.

일반 권한 UI와 관리자 실행기는 현재 사용자에게만 열린 Medium 무결성의 앱 전용 파이프를 사용한다. 실행 파일 식별자와 생성 시각, 부모/자식 세션 검증은 그대로 유지한다. 설정 저장과 지원 진단 로그의 잠금은 세션 간 공유한다. 운영체제의 UAC나 전역 보안 정책은 바꾸지 않는다.

일반 작업의 자동 연결은 `AllowPromptingForCredentials=false`로 현재 Windows 인증을 사용하며 인증 창을 띄우지 않는다. 자동 연결 자체의 대기는 30초로 제한하고 실행기 시작 응답은 기존의 별도 기한을 사용한다. 설정의 명시적인 연결도 자동 인증부터 시도한다. 인증 실패 코드 `2055`를 받은 경우에만 같은 요청에서 한 번 `AllowPromptingForCredentials=true`로 Windows 인증을 허용한다. 실패한 인증이나 사용자가 인증 중인 연결을 일반 작업에서 다시 요청하지 않는다. 명시적인 연결에서는 `PromptForCredsOnClient=true`로 클라이언트의 Windows 인증 창을 요청하고 `AllowCredentialSaving=true`로 기억 선택지 표시를 허용한다. COM 설정값의 왕복 확인은 실제 창에서 선택지가 보이거나 인증을 재사용하는지 검증한 것이 아니다. 저장 여부는 사용자가 Windows 창에서 선택하며, 앱은 암호나 저장된 자격 증명을 읽거나 기록하지 않는다. 자동 연결에서는 저장 선택지를 표시하지 않는다. 같은 RDP 구성과 실행기를 사용한다. 로그인 대상은 현재 Windows 사용자로 지정하고 COM 값을 다시 확인하며, 암호를 앱에 읽거나 저장하는 경로를 추가하지 않는다. 인증 정보가 없어 자동 연결이 실패하면 이를 성공으로 처리하지 않는다.

Windows가 명시적인 연결에 로그인 확인을 요구하면 사용자가 Windows 보안 창에서 완료한다. 환경을 유지하는 동안에는 다시 연결하지 않는다. 새 연결에서 인증이 다시 요구될 가능성을 숨기거나 자동 로그인을 약속하지 않는다. 명시적인 Windows 로그인은 사용자 취소나 실제 연결 실패 전까지 유지하고 설정에 로그인 대기를 표시한다. 사용자 인증 대기는 자동 연결이나 실행기 시작의 시간 제한에 포함하지 않는다. 연결 대기 중 작업 취소와 환경 종료가 가능하다. 상태 조회, 화면 관측, 해상도 확인과 기존 작업 제어는 환경을 새로 만들지 않는다. 끊긴 연결에서는 실패를 표시하고 기존 작업 기록의 취소만 처리하며, 새 연결은 명시적인 연결 또는 작업 시작 요청에서만 생성한다. 실행기는 연결 활성화만으로 시작하지 않는다. RDP 클라이언트의 `OnLoginComplete`와 Windows 세션의 실제 로그인 시각·로그인 사용자를 모두 확인한 뒤 요청한다. WTS 사용자 토큰이 먼저 준비된 것만으로 요청하면 작업 스케줄러가 접수한 작업을 시작하지 않는 로그인 초기화 경합이 발생할 수 있다. 로그인 완료 후 실행기 시작을 30초까지 기다리며, 실행기 시작 실패만으로 살아 있는 Windows 연결을 닫지 않는다. 같은 연결에서 재시도할 때는 새 실행 주소를 사용하므로 이전 대기 실행기가 새 시도를 완료로 덮어쓸 수 없다. Windows 연결 자체가 끊어진 경우에는 새 연결의 인증이 필요할 수 있다.

분리 연결과 서버 포인터 이동 차단 속성은 설정 뒤 실제 COM 값을 다시 읽어 확인한다. Windows 연결 이벤트는 기존 로컬 관측 저장소의 `game-environment` 기록에 단계와 오류 코드, 소유 프로세스 식별로 남기며 자격 증명은 기록하지 않는다. 잘못된 내부 실행 환경 명령은 일반 GUI를 열지 않고 거절한다. 연결 소유 실행기가 초기 설정에서 실패하거나 시작되지 않으면 로그인 대기 기한까지 기다리지 않고 즉시 시작 오류를 반환한다. 실행 대기 중 `IRunningTask.Refresh`가 실행 인스턴스가 없다는 코드 `0x8004130B`를 반환하면 예약 결과가 아직 실행 전·대기·실행 중인 경우만 대기를 유지한다. 실제 종료·실패 결과와 다른 COM 오류는 실패로 처리하고, 실행기 시작 오류의 원래 예외 종류와 코드를 지원 진단에 기록한다. 연결을 기다리는 동안에도 설정의 기존 상태 표시를 갱신한다.

## 검증 상태 (2026-10-03)

Windows 로그인 완료 뒤 실행기가 첫 요청 직후 종료되는 권한 오류를 수정했다. 앱 전용 파이프를 만들 때 사용자 ACL과 Medium 무결성을 함께 지정하며, 후속 연결에 첫 인스턴스 전용 플래그를 재사용하지 않는다. 연결 용량을 확보한 뒤 리스너를 만들고 실제 리스너 생성 후에만 준비 완료를 기록한다. 겹치는 연결의 독립 응답과 재생성, 보호된 사용자 ACL을 검사했다. 인증된 연결을 유지한 설치본 교체와 같은 연결에서 실행기 복구를 확인했으며, 설치본 관리자 실행기에 동시에 보낸 상태 요청 12개가 모두 같은 자식 세션에서 정상 응답했다.

숨긴 자식 세션의 실제 원신에서 화면 캡처, 게임 진입, 포인터 클릭, 카메라 입력 묶음, Escape 메뉴 열기와 닫기를 확인했다. 게임 카메라 입력 20초가 실행되는 동안 사용자 세션의 새 메모장에 80자를 입력했으며 문서 입력과 게임 실행이 모두 완료됐다. 사용자 세션의 커서와 포커스는 게임 입력 전후 유지됐다. 사용자가 자기 업무를 병행하는 확인은 요청에 따라 후속 검사로 남겼다.

직접 조작으로 전환한 화면에서 메뉴를 열고 닫은 뒤 자동 관제로 돌아왔다. 자동 복귀는 기존의 새 관측 게이트를 유지하며 인증 연결과 게임은 종료하지 않는다. 스캐너도 별도 창 없이 자식 세션에서 시작했고 협력적 중단 후 스캐너와 작업 실행기가 종료됐다. 취소 상태와 기존 계정 자료 보존을 확인했으며 전체 수집 성공으로 판정하지 않았다. 모든 검사는 기존 관제와 작업 저널을 사용했다.

초기 검증 연결은 이전 빌드의 1280×720 화면이었다. BetterGI의 기본 지도 인식은 이 화면에서 잘못된 이미지 영역으로 실패했다. 새 연결과 AI 프리셋의 기준을 함께 1920×1080으로 변경하고, 지도 인식·경로 이동·비경·카드 자동화는 필요한 최소 높이를 실행 전에 검사한다. 대화 등 해상도 요구가 다른 기능은 같은 제한을 받지 않는다. 현재 연결에서 지도 관측 요청은 약 1.9초 안에 실패로 기록되며 BetterGI를 시작하지 않았다. 전체 환경 종료 후 게임, 언락커, 작업 실행기와 연결 소유 프로세스가 모두 종료되는 것을 확인했고 업데이트 중 유지하던 임시 실행 이미지 링크도 제거했다. 새 1080p 연결은 Windows 로그인 완료를 확인하지 못한 상태에서 대기 시간이 지나 종료됐다. 추가 인증 창을 반복 생성하지 않았으며, 지도·경로 성공은 다음 사용자 로그인 이후 실제 확인이 필요하다.

BetterGI가 실패한 프로젝트의 종료를 기록하고 작업 묶음의 종료 시각은 남기지 않는 경우도 실패로 판정한다. 성공은 전체 묶음 종료와 각 프로젝트의 성공 기록이 모두 필요하다. 종료 시각이 없는 실패, 진행 중인 상태, 부분 성공과 혼합 작업의 해상도 요구를 입력 없는 검사에 포함했다. 설치본 검증을 완료하기 전까지 목표를 완료로 취급하지 않는다.

현재 인증 구성은 실제 Windows RDP COM 제어에서 자동/명시 연결 설정을 왕복 검사했고 전체 앱 회귀 검사, 번역 및 공개 소스 경계 검사를 통과했다. 설치본에 반영한 자동 연결은 약 1.1초에 로그인 실패 코드 `2055`로 종료했다. 구성과 연결 시작, 연결 종료가 기록됐으며 로그인 완료나 실행기 준비는 확인되지 않았다. 오류 설명이 빈 문자열인 경우에도 숫자만 표시하지 않고 Windows 로그인 실패와 설정의 연결 진입점을 표시한다. 현재 환경의 자동 인증 성공, 재시작 뒤 인증 재사용, 새 1080p 환경의 실제 게임/자동화 성공은 이 결과로 검증된 것이 아니다.

최신 명시적 연결에서는 Windows 로그인과 셸 시작이 성공했지만 실행기 시작에서 실패했다. 사용자는 해당 Windows 로그인 창에 기억 선택지가 없었다고 확인했다. 현재 Windows 제어의 초기 `AllowCredentialSaving`과 `PromptForCredsOnClient`는 모두 false였다. 자동/명시 연결에 대한 세 속성 왕복 검사와 실행 대기·실패 검사, 한국어 전체 검사 및 수정본 영어 전체 검사, 번역과 공개 소스 경계 검사를 통과했다. 저장 선택지 허용 속성만으로 재인증 문제를 해결한 것으로 판정하지 않으며 클라이언트 인증 창 설정과 실행기 대기 처리의 실제 설치본 검증이 필요하다.

최신 명시적 연결은 Windows 로그인과 셸 시작까지 성공했다. WTS 로그온 직후 요청한 일회성 작업은 `0x41303`(아직 실행하지 않음) 상태에 남았고, 클라이언트 로그인 완료 이벤트와 셸 시작 후 같은 등록 작업을 같은 자식 세션에서 다시 실행하자 실행기 준비 응답이 도착했다. 일회성 등록은 제거됐다. 새 시작 조건은 두 로그인 신호를 모두 기다린다. 이 시작 조건을 적용한 새 인증 연결은 아직 실제 확인하지 않았다.

이 연결을 유지하려고 설치 실행 파일을 옮기는 과정에서 이전 경로 비교가 소유자를 거절해 연결과 실행기가 종료됐다. 파일 식별자로 소유권을 고정하도록 수정했으며, 로그인과 입력이 없는 실제 별도 프로세스로 실행 파일 이동·교체와 소유권 유지, 대체 파일 거절, 잘못된 생성 시간·세션 거절, 종료 후 캐시 거절을 검사했다. 한국어와 영어 전체 앱 검사 및 번역·공개 소스 경계 검사를 통과했다. 실제 인증 연결을 유지하는 업데이트 성공과 자동 인증 재사용을 이 검사로 대신 판정하지 않는다. 기억 선택지의 실제 표시·저장 여부는 확인되지 않았으며 사용자에게 추가 로그인을 요청하지 않았다.

Microsoft의 현재 Power Automate 자식 세션 안내도 Windows 정책·구성에 따라 자동 인증이 불가능할 수 있으며 같은 연결을 연속 작업에 재사용하도록 안내한다. 이 PC에서 기본·새·저장 자격 증명 위임의 허용 및 거부 정책 값은 모두 명시적으로 설정되지 않았다. 이를 특정 거부 정책의 증거로 취급하지 않는다. 기억 선택지 속성 설정, 자동 인증 성공, 인증된 연결 보존은 서로 다른 검증 항목이며 보안 정책 변경으로 검사 실패를 숨기지 않는다.

명시적 연결이 인증 대기 10분 뒤 종료되는 동작을 실제로 확인했다. 사용자 인증 대기를 공통 연결 단계로 분리하여 취소나 실제 연결 실패 전까지 유지하고, 로그인 완료 후 실행기 시작에는 별도의 제한 시간을 적용한다. 인증 대기가 기한을 넘긴 뒤 준비 응답으로 이어지는 경우, 이후 실행기 제한 시간, 자동 연결 제한 시간, 취소·실패·소유 프로세스 종료를 입력 없는 회귀 검사로 확인했다. 한국어·영어 전체 검사와 번역·공개 소스 검사를 통과했다. 실제 자동 인증과 게임 조작 검증은 사용자 인증 완료가 없어 진행하지 않았다.

## 연결 수명과 복구 경계

연결 시작·복구·종료 요청은 현재 사용자의 공통 수명 잠금으로 직렬화한다. 새 연결의 소유권 기록을 게시한 뒤 잠금을 풀고, 인증을 기다리는 동안에는 다른 요청의 취소·종료를 허용한다. 작업 요청은 인증 실패나 사용자의 인증 대기를 재시도하지 않으며, 명시적 연결만 Windows 기본 인증을 먼저 시도한 뒤 필요한 경우 인증 창을 한 번 요청한다. 인증 중에는 사용자가 취소하거나 실제 연결이 실패할 때까지 연결을 유지한다.

실제 Windows 로그온을 완료한 연결에서 실행기만 손실되면 같은 연결 안에서 한 번 복구한다. 실행기 시작은 30초로 제한하며, 셸 초기화 중 예약된 요청에 실행 인스턴스가 생기지 않으면 5초 이후 같은 등록 작업을 한 번 다시 실행한다. 세션당 실행기 잠금으로 중복 실행을 방지한다. 복구에 실패해도 인증된 연결은 유지하며 설정의 연결 동작이 실행기만 다시 시작한다. 일반 연결 장애는 무인 재연결 대상이지만, 인증 실패는 명시적 연결이 필요하다.

이미 로그인한 연결의 일시 끊김은 Windows 자동 재연결을 최대 세 번 허용하고 같은 자식 세션의 복구를 최대 30초 기다린다. 재연결 중에는 Windows의 실제 연결 상태에서 대기 상태를 파생하여 새 게임 입력을 전달하지 않으며 소유자와 실행기는 유지한다. 로그인 완료 후에는 인증 창 요청을 비활성화한다. 초기 인증 실패, 인증 오류와 재시도 소진은 자동 로그인 요청으로 이어지지 않는다. Windows 재연결 이벤트를 중단 값으로 처리하던 결함과 완료 이벤트 누락을 수정했으며, 실제 인증된 세션의 재연결 성공은 별도의 실사용 검증이 필요하다.

인증 실패는 같은 Windows 로그온에서만 재시도를 막는다. Windows가 세션 번호를 재사용해도 이전 연결 소유자의 생성 시각이 현재 실제 로그온보다 앞서면 이전 실패를 꺼진 상태로 취급하여 다음 작업의 자동 연결을 허용한다. 시간 정보가 없는 실패는 임의로 지우지 않는다. 이 구분은 새 로그온 뒤의 연결 기회를 복구하는 것이며 Windows 자동 인증 성공을 보장하지 않는다.

연결 소유자와 게임 실행기는 공통 통신 대기 함수를 사용한다. 취소는 파이프를 닫아 비동기 완료를 기다리며, 완료 콜백이 사용하는 대기 핸들을 먼저 폐기하지 않는다. 실행기 종료 응답을 기록한 뒤 통신 대기를 취소한다. 초기 연결 실패에서는 확인되지 않은 다른 자식 세션을 종료하지 않는다. 연결 예외의 종류·원래 코드·앱 호출 위치는 개인 내용 없는 공통 지원 진단에 기록하고 연결 저널에도 코드를 남긴다. 실패한 연결 소유자는 정상 종료 코드로 보고하지 않는다.

전체 앱 업데이트는 연결 소유자가 살아 있는 동안 준비된 패키지를 유지한다. GUI와 독립 업데이트 실행기가 같은 잠금 기준으로 검사하며, 업데이트 실행기는 연결 시작과 같은 수명 잠금을 사용해 검사와 설치 사이에 새 연결이 생기는 경쟁을 막는다. 업데이트 중에는 새 실행 환경 시작을 거절한다. 종료는 응답하지 않는 실행기에도 제한 시간을 적용하고 소유한 연결을 종료한다. 연결·복구 단계와 경과 시간은 기존 관측 저장소에 남긴다. 설정은 인증 필요, 인증 대기, 실행기 복구 필요를 구분한다.

동시 요청·취소·실패·인증 대기 회귀 검사, 한국어·영어 전체 검사와 실제 이전/새 프로세스의 파일 교체 후 양방향 소유권 확인을 통과했다. 추가 승인된 Windows 기본 인증 프로토콜 비교는 연결 매개변수 오류로 실패했다. 인증 창과 게임 입력 없이 시험 프로세스·실행 파일을 정리했고 OS 보안 정책은 바꾸지 않았다. 이 결과는 자동 인증 성공이나 새 환경의 전체 게임 조작 검증을 뜻하지 않는다.
