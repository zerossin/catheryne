# 나선비경·지맥 제압전 출전 준비

플레이 메뉴의 두 탭은 전투 전에 파티를 정하고 비교하는 도구다. 나선은 12층 전반·후반 두 파티를, 지맥은 선택한 난이도의 세 파티를 함께 추천한다. 환상극의 막·선택·활력 관제를 재사용하지 않는다.

## 통계와 내 육성

Lightkeepers의 공개 `/api/static`가 제공하는 최신 시즌의 YShelper 파티 통계를 사용한다. 캐릭터 전체의 단독 픽률이 아닌 **파티 전체 보유자 중 사용 비율**을 사용한다. `usage_total / has_total`과 공개 픽률의 일치를 검증하고, 각 전장에 출전한 비중도 반영한다. 개별 파티의 사용 수와 보유 수는 저장한다. 전체 표본 수, 난이도, 서버, 돌파·무기 수준은 확인되지 않았으므로 unknown을 유지한다. 서버별 개방일 경계는 추정이며 통계 시즌 표기가 공식 개인 전적을 대체하지 않는다.

정확한 영문 이름으로 보유 캐릭터와 대응시킨다. 픽률×전장 비중을 주요 사전 근거로, 기존 공통 육성 점수와 레벨을 준비 상태로 반영한다. 육성 점수는 피해량·원충 충족·생존·클리어 확률이 아니다. 정보가 누락되어도 0점으로 처리하지 않는다. 확인된 육성 점수는 순위에 계속 반영하고, 누락 영역은 중립값으로만 처리한다. 완성 점수로 외삽해 표시하지 않는다. 1~3인 도전 파티는 기본 4인 추천에서 제외한다. 추천 근거에서 한계를 확인할 수 있다.

전장별 상위 100개 후보를 함께 탐색해 최대 세 가지 편성을 제시한다. 전장별 최고 픽률을 따로 고르는 탐욕적 선택을 사용하지 않는다. 보유하지 않은 캐릭터는 제외하며, 캐릭터 및 확인 가능한 장비 개체 중복을 검사한다. 여행자 원소 형태는 같은 캐릭터로 본다. 지맥 난이도 1~3은 전장 간 재사용을 허용하며 4~6은 제한한다. GOOD의 실제 개체 ID가 없는 HoYoLAB 장비는 중복 검증 완료로 표시하지 않는다. 알려진 개체 충돌만 배제할 수 있다.

공개 통계에서 자신의 조합을 찾지 못하면 직접 편성을 저장할 수 있다. 직접 편성에는 픽률을 만들어 붙이지 않는다. 자동 추천은 전장별 사용 경향에 따른 후보 제안이며 적의 면역·쉴드·기믹, 팀 원충과 사이클을 시뮬레이션하지 않는다. 선택한 편성의 AI 검토에서 해당 부분을 확인한다. 지맥의 시작 원소 에너지, 난이도별 적 능력 차이를 특히 고려해야 한다.

## 저장과 기록

편성 저장은 당시 캐릭터·장착 무기·성유물·육성 평가·사이클 메모, 목표, 난이도, 계정 스냅샷과 통계 참조를 고정한다. 계정 최신화가 저장한 빌드를 덮어쓰지 않는다. 계정 또는 시즌이 바뀌면 화면 진입과 주기적 확인에서 추천을 자동으로 갱신한 뒤 저장할 수 있다. 난이도 변경도 자동 재계산한다. 추천 갱신은 저장된 편성과 결과 기록, 입력 중인 메모를 덮어쓰지 않는다. 자료와 난이도가 같으면 기존 추천을 유지한다. 직접 편성은 현재 장비를 새 버전으로 저장한다.

기록은 성공/실패, 시간(선택), 결과 근거와 실제 사용 장비 확인을 요구한다. 예상 결과와 실제 결과를 혼합하지 않는다. 나선 시간은 전후반을 합친 방 전체 시간이다. 별은 방별로 저장하며 다른 재도전의 별을 유지하는 방식에 맞춰 요약한다. 지맥 개인 최고 기록을 합칠 때는 같은 시즌·난이도의 캐릭터·장비 호환성을 검사한다. 이는 사용자 기록상의 조합이며 게임 안에서 현재 활성화된 공식 전적이 아니다. 개체 ID가 불명확하면 합산도 미검증이다.

비교는 같은 시즌·난이도·목표의 빌드만 허용한다. 편성·장비·사이클 변경과 시도 수·성공 수·최고 및 중앙 시간 기록을 제공한다. 표본이 없는 시간은 null이다. 기록 향상을 특정 장비 변경의 인과적 효과로 단정하지 않는다. GUI는 결과 기록과 최고 시간 비교를 제공하며 전체 자료는 AI 도구에서 확인할 수 있다.

## 공통 서비스와 데이터

`EndgameKnowledge`는 공개 자료를 검증하고 내용 해시로 고정한다. 한 시간 캐시, 화면 진입·표시 중·추천 실행 시 내부 갱신, 실패 시 기존 유효 자료 보존을 사용한다. `EndgamePlanning`은 계정 해석과 공통 육성 평가를 재사용한다. `EndgameService`의 한 경로에 GUI와 MCP 도구가 연결된다.

도구: `catheryne_endgame(command, mode, parameters)`. mode는 `abyss|stygian`, command는 `status|prepare|recommend|save_build|record|compare|knowledge|capture`다. 상태 변경에는 낙관적 revision 검증과 event_id 재시도 보호가 필요하다. 공개 조회에는 개인 명단·장비·쿠키를 전송하지 않는다. 개인 자료는 기존 비공개 데이터 루트의 `endgame/accounts/<account hash>/`에 저장한다.

`추천 전에 계정 최신화`를 선택하면 기존 HoYoLAB 계정 최신화 서비스가 실행된다. 실패를 표시하고 추천은 중단한다. 기존 자료로 진행하려면 체크를 해제해 다시 실행한다. 게임 입력이나 자동 전투는 수행하지 않는다. UI의 `AI와 검토`는 질문 초안을 준비하며 사용자가 전송한다.

공개 자료: [Lightkeepers](https://lightkeepers.moe/), [파티 통계 응답](https://lightkeepers.moe/api/static). 전투 규칙과 구체적인 기믹 판단은 해당 시즌 게임 화면 및 공식 안내를 우선한다.

검증: 시즌·분모 검증, 실패 시 캐시 보존, 픽률 후보의 보유 자료 매칭, 공동 파티 탐색, 난이도별 재사용, 장비 충돌, 자료 누락, 계정 변경 후 스냅샷 불변, revision·멱등성, 결과 확인, 비교 조건, 두 화면과 좁은 추천 카드 렌더링을 self-test로 확인한다.

## 파티 화면

내 계정 캐릭터 탭의 공통 카드와 같은 초상화·원소·돌파·레벨 디자인을 사용하며 파티마다 한 줄에 네 장을 배치한다. 픽률은 전장 제목 옆에 표시한다. 카드 선택은 해당 캐릭터의 접힌 상세를 연다. 전장 사용 비중·육성 점수는 상세의 막대로 표시하고 장비 및 미확인 정보도 접힌 상세에 보존한다. 첫 번째 추천을 기본으로 펼치고 다른 추천은 접혀 있다. 저장된 편성도 같은 카드 행을 사용한다. 출전 설정은 접힌 영역에 두며 통계 갱신 버튼은 없다.

## 2026-10-01 후속: 시즌·좌석·반응형 카드

지맥 통계의 원본 키는 화면 전장 순서와 다르다. 제공자의 공개 클라이언트는 top=field_1_rate, middle=field_3_rate, bottom=field_2_rate로 대응시킨다. EndgameKnowledge schema 2가 이를 물리 전장 1·2·3으로 정규화하며 GUI/AI/추천은 같은 정규화 자료를 사용한다. 이전 매핑으로 생성한 추천은 무효화하지만 저장된 편성·실제 기록과 시즌 식별자는 바꾸지 않는다. 참고: https://lightkeepers.moe/_app/immutable/chunks/Df3LKeLm.js

원문 멤버 배열은 이름순이며 스킬 사이클 정보가 없다. PartyRoles의 기본 좌석은 주력 딜러 → 서브 딜러 → 지원 → 회복·보호막 순이다. 유연한 드라이버는 별도 주력 딜러가 없을 때 앞에 둔다. 역할을 모르는 캐릭터는 지원 위치에서 기존 순서를 보존한다. KQM 캐릭터 가이드를 기준으로 분류하며, 고정된 스킬 사용 순서로 해석하지 않는다. 저장 파일은 수정하지 않고 상태의 화면·AI 투영에서 같은 좌석 순서를 사용한다.

내 계정 카드 디자인을 공유하되 파티 카드의 초상화 영역은 창 너비에 따라 정사각형으로 유지한다. 네 카드의 폭과 간격은 동일하다. 추천 및 저장된 편성의 상세와 대안은 첫 확장 때 생성한다. 탭 진입 시 계정·상태 파일은 백그라운드에서 읽고 같은 이미지의 읽기·검증·디코딩 요청은 공통 BitmapCache에서 합친다. 화면을 벗어난 이전 로딩 결과는 적용하지 않는다. 자동 통계 확인은 작성 중 입력을 재생성하지 않는다.

현재 시즌은 환상극과 같은 PanelUi.SeasonHeader를 맨 위에 사용한다. 지맥의 세 적 이름·아이콘은 같은 시즌 통계 메타데이터에서 자동으로 가져와 시즌 카드와 각 전장에 표시한다. 원문이 한국어를 제공하지 않는 새 적은 원문 이름을 보존한다. WebP 아이콘은 앱에 포함된 bounded decoder로 읽는다. 난이도는 보통·숙련·어려움·위험·극한·절망을 숫자와 함께 표시한다.

‘이 편성 저장…’은 저장 입력란을 펼쳐 이름에 초점을 맞춘다. 실제 저장은 기존 ‘편성 저장’ 버튼으로 확정한다. 나란히 배치한 ‘AI 상담’은 해당 추천 ID와 옵션, 목표를 포함해 기존 채팅 질문 초안을 준비한다. 저장된 편성의 기존 AI 검토도 유지한다.

현재 시즌 역할 확인: [베샤](https://keqingmains.com/i/vesna/), [보다니차](https://keqingmains.com/q/vodyanitsa-quickguide/), [니콜](https://keqingmains.com/q/nicole-quickguide/), [바르카](https://keqingmains.com/q/varka-quickguide/), [로엔](https://keqingmains.com/q/lohen-quickguide/), [미즈키](https://keqingmains.com/q/mizuki-quickguide/). 이 역할 기준은 좌석 기본값이며 캐릭터의 모든 변형 빌드나 팀별 피해 비중을 판정하지 않는다.


### 시즌 상단과 편성 저장 피드백 (2026-10-01)

환상극·나선·지맥은 하나의 시즌 상단 구성(시즌 제목, 26 DIP 아이콘 행, 기간)을 공유한다. 지맥은 전장 순서로 보스 얼굴, 나선은 전반·후반별 적 얼굴을 표시하고 방 번호·이름·시즌 원문은 툴팁으로 보존한다. 기본 적 한국어 이름은 공통 게임 카탈로그의 ID와 정확한 이미지 키로 연결하며, 미수록 이름은 원문으로 남긴다. 시즌 변형 이름을 기본 적 이름으로 덮어써 저장하지 않는다. 실제 편성 저장 성공 시 체크와 저장된 이름을 표시하며, 편성·목표·메모를 수정하면 체크를 해제한다. 탭 진입에서 계정·카탈로그·설정 읽기는 배경 작업, 이미지 요청은 기존 제한 캐시를 사용한다.

### 공통 시즌 일정·완료 상태

캘린더·환상극·나선·지맥은 ChallengeSeasons의 계정별 HoYoLAB 관측을 공유한다. 나선·환상극의 act_calendar 공식 시간과 is_finished, 지맥 hard_challenge의 현재 schedule 및 single 전적을 사용한다. 지맥은 세 전장과 유효한 최고 기록이 확인될 때 달성 난이도를 함께 표시하며 멀티 기록·부분 클리어·이전 시즌으로 솔로 완료를 추정하지 않는다. 지맥 일정도 캘린더에 투영한다.

기간은 모두 UTC 원본을 같은 CalendarPanel.Timing으로 PC 현지 시각까지 표시한다. 공식 자료가 없으면 규칙/통계 기간을 사용하되 완료를 추정하지 않고 출처·관측 시각·미확인 여부를 도움말에 보존한다. 통계의 서버 벽시계는 PC 시간대로 이동시키지 않는다. 공식 시즌 시작일과 다른 통계를 현재 시즌의 적·추천으로 표시하지 않는다. 저장한 편성·수동 기록은 별도로 보존한다.

탭 진입·추천·캘린더 최신화에서 공식 자료를 백그라운드 조회한다. 5분 캐시와 공통 조회 게이트로 중복 호출을 합치며, 현재 기간과 선택한 계정으로 기록을 제한한다. 환상극의 최초 상태 조회도 UI 스레드 밖에서 처리한다.
