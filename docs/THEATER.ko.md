# 환상극 관제

## 목표와 완료 기준

플레이 → 환상극에서 자료 준비 상태를 확인하고 기존 AI 채팅으로 이어진다. 채팅에서 직접 요청해도 같은 도전 서비스를 사용한다. 사용자가 전투를 수행하고, 캡처마다 AI가 실제 상태를 증분 갱신한 뒤 선택지·출전 조합과 남은 도전 계획을 판단한다.

완료 기준은 현재 시즌 자료 준비, 채팅에 연결된 재개 가능한 도전 기록, 캡처 전달, 출전·강화 상태 정합성, 전투 직접 수행, 기존 기능 보존이다. 실제 게임 완주 성능은 별도 실전 검증이 필요하며 자동 테스트 통과와 구분한다.

## 단일 원본과 실행 흐름

- 계정: 기존 불변 계정 스냅샷을 참조한다. 캐릭터·장비 조회는 기존 Account/AccountMerge의 표현과 계산을 공유한다.
- 지식: 시즌·규칙·카드/반응 강화 공개 자료를 개인 데이터 위치의 불변 참조 스냅샷에 캐시하고 도전이 그 버전을 참조한다. 출처·확인 시각·누락을 보존한다.
- 도전: 하나의 도전 JSON에 관측·추천·실제 선택·종료 이벤트를 추가한다. 현재 상태는 이벤트 재생으로 계산한다. GUI/MCP/채팅이 별도의 상태 표를 갖지 않는다.
- 계획: 추천과 실제 결과를 구분한다. 상태 변경 이후 추천은 효력을 잃지만 이전 계획은 비교 문맥으로 남는다.
- 입력: 환상극 도구는 게임 입력을 보내지 않는다. 화면 획득은 기존 GameCapture/CaptureStore를 사용한다.

자료 준비 → 목표·난이도 확인 → 계정 자동 최신화 작업 → 최신 계정/공개 자료/판단 원칙을 고정한 도전 생성 → 전체 참가 캐릭터와 후반 비축 역할 검토 → 게임 준비 화면 확인 (재개는 고정 자료 유지) → 캡처 → 확인된 변화 관측 → 다각도 비교와 추천 → 사용자 선택/전투 → 다음 캡처를 반복한다. 화면을 모르는 상태에서 결과나 출전 기회를 추정해 변경하지 않는다.

## 자료 경로 조사 (2026-10-01)

1. [genshin.py의 전적 클라이언트](https://github.com/seriaati/genshin.py/blob/master/genshin/client/components/chronicle/genshin.py)와 [환상극 모델](https://github.com/seriaati/genshin.py/blob/master/genshin/models/genshin/chronicle/img_theater.py): role_combat GET, role_id/server/need_detail=true. 시즌 일정·완료 기록·출전 캐릭터·획득 카드 전적이 있다. 실시간 선택지와 현재 남은 출전 기회의 원본으로 사용할 수 없다. 기존 HoYoLAB 인증과 읽기 전용 통신을 확장하며 패키지를 추가하지 않는다.
2. [genshin-db](https://github.com/theBowja/genshin-db): 캐릭터/무기 등 정적 정보 보충. 계정/게임 카탈로그의 기존 경로를 유지하며 환상극 전용 캐릭터 사전을 중복 생성하지 않는다.
3. [환상극 수집 오픈소스](https://github.com/tuananh511/genshin-ai-agent/blob/main/genshin_agent/theater_collector.py): 시즌별 MediaWiki API 사용과 시즌 자료 누락 처리 방식을 확인했다. 코드를 복제하거나 외부 플래너를 실행하지 않는다.
4. MediaWiki parse API의 규칙, Events, 정확한 시즌 페이지를 런타임에서 읽는다. Events에는 카드와 반응 강화 설명이 있다. 공동체 자료이며 게임 내 확인보다 우선하지 않는다. HTML 주석의 빈 전투 초안은 제거한다. 서버의 UTC 오프셋과 04:00 갱신을 반영하고 이전 시즌을 현재 시즌으로 대체하지 않는다.
5. [공식 환상극 소개](https://www.hoyolab.com/article/29513513), [공식 플레이 팁](https://www.hoyolab.com/article/30474962): 공식 기본 안내의 참조 경로. 오래된 출시 안내를 현재 모든 난이도의 확정 규칙으로 고정하지 않는다.

조사한 2026-10 시즌 페이지의 전투 항목은 주석 안의 빈 초안이었다. 해당 시즌이 적용되면 전투 구성은 미준비로 표시하고 캡처에서 확인한다. 실제 적용 시즌은 서버의 갱신 시점으로 정하며 한국 날짜가 바뀌었다는 이유만으로 다음 시즌을 적용하지 않는다. 접근 실패·부분 자료·미보유는 서로 구분한다.

## 관측과 추천 계약

도전은 채팅에 귀속된다. 변경에는 session_id, expected_revision, 고유 event_id가 필요하다. 동일 이벤트 재전송은 한 번만 적용하고 다른 내용으로 재사용하면 거절한다. 최신 상태와 맞지 않는 변경을 거절한다.

관측은 출처·근거와 함께 필요한 필드만 제공한다. 캐릭터는 보유/체험/친구 지원, 출전 가능 여부, 남은 기회를 기록하고 모르는 수치는 null로 유지한다. 카드·반응 강화는 종류와 단계, 실제 효과 설명을 기록한다. 선택지는 현재 화면 전체 목록이다. 실제 선택 등록은 효과나 무작위 영입을 추정하지 않는다. 정정도 새 관측 이벤트로 남긴다.

추천은 지금의 근거, 남은 도전 계획, 대안을 함께 보관한다. 출전 불가/남은 기회 미확인 캐릭터와 없는 선택지는 추천으로 등록할 수 없다. AI는 적 기믹, 생존/회복, 원소 부착과 반응, 육성·장비, 남은 기회, 후반 필수 역할, 자원, 무작위 영입 실패와 사용자 운용을 검토한다. 정밀 피해 시뮬레이터나 허위 성공 확률을 만들지 않는다.

전투 중에는 사용자의 다음 캡처를 기다린다. 종료는 최종 결과 화면 관측과 근거를 요구한다. 코칭 종료는 게임 완주로 기록하지 않는다.

## 화면과 채팅

환상극 페이지는 서버 기준의 적용 연월·종료 시각과 허용 원소, 규칙/카드·강화/시즌 구성/전투 구성/계정 자료 및 파티·반응/파티 통계 일곱 항목을 기본 화면에 표시한다. 전투는 실제 자료가 확인된 기본 막과 추가 전투 개수, 계정은 확인된 캐릭터 수를 표시한다. 출처·확인 시각과 장비 수는 접힌 자료 상세에서 확인한다. 시작/이어가기와 자료 새로고침은 공통 40px·동일 너비·8px 간격의 작업 행을 사용한다. 진행 중인 도전은 저장된 목표와 현재 관측 막을 표시한다.

새 도전의 목표와 난이도는 같은 채팅에서 먼저 확인한다. 이미 전달한 조건은 다시 묻지 않는다. 계정 캐릭터 전체와 실제 환상극 참가/출전 가능 캐릭터를 구분하고 개막·체험·지원 후보 및 후반 비축 역할을 검토한 뒤 게임 준비 화면으로 대조한다. 출전 조합은 각 막에서 남은 출전 기회와 현재 선택지에 따라 다시 결정한다.

공통 AiTaskStore에는 도전 원장에서 다시 만들 수 있는 작업 투영을 저장한다. 별도의 도전 상태 저장소나 게임 입력 엔진은 만들지 않는다. 같은 도전은 차례가 바뀌어도 하나의 상자를 갱신하며 다음 판단 차례로 이동한다. 사용자의 다음 선택을 기다리는 `waiting`은 오류/실행 중/완료와 구분하고, 앱 재시작으로 실패 처리하지 않는다. 관제 종료는 원장의 end를 기록하고 게임 완주와 구분한다. 현재 응답이 해당 환상극 판단 차례이면 그 응답도 중단하며, 게임 입력/조작권 변경이나 다른 차례의 답변은 중단하지 않는다.

상자에는 실제 완료 막 수/확인된 전체 막 수, 현재 막 또는 추가 도전 이름, 현재 선택지의 화면 위치·확인된 비용과 추천, 출전 파티 초상화·남은 출전 횟수, 번호가 붙은 스킬 순서를 표시한다. 미확인 후보는 초상화를 추측해 붙이지 않으며 확인된 참가 명단에서 이름을 선택해 동일 observe 경로로 정정할 수 있다. 정정은 추천을 무효화하고 다음 판단을 기다린다. 캐릭터 영입 추천은 실제 보이는 이름과 참가 명단의 같은 캐릭터 이름 대조를 통과해야 하며 스킬 순서는 추천 파티 안의 캐릭터만 사용한다. 명단 대조가 시각 인식의 정확성을 보증하지는 않는다.

판단은 현재 화면의 캡처와 같은 채팅의 판단 요청을 한 번에 실행한다. 응답/캡처/정정 중에는 중복 요청을 막는다. 확인된 완료 막 수만 진행도를 변경하며 시간이나 AI 판단 횟수는 진행도를 올리지 않는다. 추가 도전은 기본 막 수와 별개로 표시한다. 보유 카드, 반응 강화, 전체 참가 캐릭터·남은 계획·대안은 펼쳐 볼 수 있고 펼친 상태는 갱신 후 보존한다. 상단 실행 표시는 환상극 판단 대기로 같은 대화에 돌아간다. 작업 기록에는 다음 판단 대기 상태를 필터할 수 있다.

환상극 탭의 원소는 카탈로그의 원본 원소 벡터와 접근성 이름·툴팁으로 표시한다. 남은 기간/완료는 CalendarPanel.Timing과 CalendarStore.Remaining을 공유한다. 같은 시즌의 최신 공식 캘린더 완료 표기를 우선하고, 해당 자료가 없으면 서버 월 경계와 현재 도전의 확인된 완료를 사용한다. 관제 종료만으로 완료 표시하지 않는다. 화면이 보이는 동안 남은 시간과 시즌 경계를 분 단위로 갱신하고 닫히면 표시 타이머를 멈춘다.

활성 환상극 채팅에서 기존 캡처 단축키를 누르면 해당 캡처를 첨부해 같은 채팅으로 판단 요청을 보낸다. AI 응답 중이면 최신 캡처를 기다려 전달하고 중단 시 대기 전송을 취소한다. 다른 채팅·환상극 도전 종료 후에는 기존 저장 동작을 유지한다. 초안과 다른 첨부는 캡처 전송에 섞지 않는다.

실행 중 지속적으로 화면을 감시하거나 전투 종료를 자동 인식하는 기능은 포함하지 않는다. 캡처 제출이 다음 판단의 명시적 계기다. 후속 자동 감지는 동일 관측 계약을 통해 연결해야 한다.

## 검증

서버별 시즌 경계, 주석 초안 제거, 캐시 재사용, 도전 재개, 이벤트 중복/충돌, 오래된 상태, 채팅 소유권, 부분 갱신, 미확인 출전 기회, 실제 선택과 추정 효과 분리, 전투 중 추천 제한, 완료 근거를 자동 검사한다. 전체 앱 검사와 공개 소스 개인정보 검사를 함께 수행한다. 캡처의 이미지 응답은 기존 채팅/MCP 이미지 경로를 사용한다.

## 선택 자동화 판단

진행 중인 플레이 대화의 사용자/응답 메시지를 읽기 전용으로 검토했다. 영입·여러 카드·파티를 매번 분리해서 판단하는 대기와 후보 오인식 정정이 병목이었다. 실제 대화/계정/스크린샷은 저장하거나 소스에 복제하지 않는다.

컴퓨터 유즈의 후보 범위는 사용자가 명시적으로 허용한 비전투 메뉴 구간이다. 장기 계획을 미리 세운 뒤 확인 가능한 영입·카드·편성만 실행하고 결과를 매번 검증하며 전투 진입 전/이름 미확인/예상 밖 메뉴에서 멈추는 흐름이 적합하다. 클릭 자동화만으로 모델 판단 시간이 줄어들지는 않는다. 이 변경은 자동 클릭·전투·상시 감시를 활성화하지 않는다. 향후 입력도 core/story-control의 기존 경로를 사용해야 한다.


## 완주 피드백과 판단 원칙

사용자가 지정한 완주 대화의 공개 사용자/AI 응답을 읽기 전용으로 검토했다. 보호막 대응보다 후반 강한 캐릭터 보존을 앞세움, 네 명을 채운 것을 실전 가능 편성으로 취급함, 실제 등록 캐릭터 이름과 지원 장비 혼동, 미확인 후보·메뉴를 추정함, 각 선택마다 전체 조사를 반복하는 지연이 확인됐다. 원문 대화, 계정과 캡처는 소스에 복사하지 않았다.

새 도전은 `TheaterPlanning.Principles`의 버전과 내용을 원장에 고정한다. 우선순위는 **현재 기믹·면역·보호막·생존 → 사용자 클리어/별 목표와 화력·운용 → 남은 모든 기본/목표 추가 도전의 출전 배분 → 카드·자원 효율**이다. 질문만으로 추천을 뒤집지 않고 변경 근거를 기록한다. 실패/시간 부족은 기존 판단을 다시 검토하는 실제 증거다.

새 파티는 전체 실제 참가 명단과 출전 인원이 확인된 뒤에만 추천할 수 있으며 기믹·생존·화력·운용·반응 다섯 `assessment`를 제출한다. failed는 추천 거절, unknown은 화면에 검증 필요로 표시한다. evidence는 AI의 근거 주장이지 외부 검증기나 피해 시뮬레이터가 아니므로 허위 내용을 완전히 방지하지는 못한다. 체험/지원 육성과 장비는 보유 스냅샷에서 자동 상속하지 않는다.

## 남은 전투 전체 계획

`battlePlan`은 전투 ID, 기본 막 번호(추가 도전은 생략), 실제 요구 조건, 편성, 근거, 대체안과 `supported|recruitment|unverified|blocked` 상태를 가진다. supported는 현재 출전 가능/양의 출전 횟수가 확인된 전체 인원 편성으로 제한하며 클리어 보장을 뜻하지 않는다. 미래 적이 미확인이면 미검증/편성 불가로 남긴다. 총 막 수가 확인된 새 파티는 남은 기본 막을 모두 포함한다. 목표에 추가 도전이 있으면 확인된 `requiredChallenges`와 `completedChallenges`로 기본 막과 별도로 계산한다. 현재 추가 도전 파티도 같은 미래 계획에서 계산한다.

프로그램은 매 관측 후 남은 모든 편성의 출전 횟수, 실제 영입 여부, 필요한 총 출전 슬롯, 알려진 출전 자원 부족과 변경 영향을 다시 계산한다. 완료된 전투는 재사용 계획과 자원 계산에서 제외한다. 신규 영입/실제 회복은 모든 남은 후보에 영향을 주고 출전 횟수 감소는 해당 캐릭터를 배정한 계획을 우선 재검토한다. 카드/반응/적/목표/규칙/실전 결과 변화는 남은 계획 재검토 대상이다. 초기 `battlePlan` 이후에는 `battleChanges`로 수정한 전투 행만 제출하고 영향받았지만 유지할 전투 ID는 `reviewedBattles`에 명시한다. 모든 영향 전투를 수정하거나 검토해야 하며, 프로그램이 기존 행과 병합한 하나의 전체 계획을 같은 검증기에 통과시킨 뒤 저장한다. 전투 범위가 바뀌면 전체 계획을 다시 제출한다. 완료된 전투나 새 전투 ID를 부분 변경으로 넣을 수 없고, 전체 제출과 부분 제출을 함께 사용할 수 없다. 변경 없는 후보와 고정 원문은 재사용한다.

이는 AI의 전투 적합성 판단과 결정적 자원 검증을 결합한 방식이다. 전체 조합의 최적성, DPS, 성공 확률을 자동 계산하지 않는다. 무작위 영입/회복은 확정 자원으로 계산하지 않으며 준비되지 않은 시즌 전투를 통계로 채우지 않는다.

## AI 입력의 범위

시작/자료 준비는 전체 응답을 제공하며 일반 상태와 변경 응답은 `view=decision`이 기본이다. 실제 관측된 명단·출전 횟수·카드·반응·선택지·목표·리비전·자료 준비 상태·계정 변경 여부·전체 자원 검증은 유지한다. 중복된 전체 계획과 반복 출처/원칙 원문 대신 남은 전투의 ID·막·제목·편성·상태·요구 조건인 `planningBoard`를 제공한다. `view=full`로 원본 전체 응답을 읽을 수 있다. `plan`과 선택적인 `battle_ids`는 필요한 남은 전투의 저장된 근거/대체안을 읽으며 기록이나 리비전을 바꾸지 않는다. GUI는 계속 같은 전체 기록에서 표시한다.

AI는 현재 적합한 후보 2~3개를 먼저 좁히고, 고정 계정/자료에서 필요한 캐릭터·스킬·근거만 읽는다. 영입·회복은 모든 남은 전투의 후보 재검토를 요구할 수 있지만 전체 자료의 재검색이나 전체 계획의 재작성을 요구하지 않는다. 전체 자원 검사와 전투 적합성 판단은 별개의 책임이며 검토 확인으로 자원 검증을 생략할 수 없다. 응답 형식은 이벤트의 의미와 무관하므로 같은 이벤트 ID를 다른 view로 재조회해도 중복 기록하지 않는다.

자체 검사에 사용하는 가상 예시(캐릭터 4명, 선택지 3개, 남은 전투 6개)의 직렬화 응답은 전체 8845바이트에서 판단 요약 3862바이트로 56.3% 줄었다. 이는 UTF-8 응답 크기 비교이며 모델 토큰·응답 시간·실전 추천 품질을 측정한 수치는 아니다.

## 최신 전투 자료와 통계

- KQM [파티 구성](https://keqingmains.com/misc/team-building/), [격변](https://library.keqingmains.com/combat-mechanics/elemental-effects/transformative-reactions), [증폭](https://library.keqingmains.com/combat-mechanics/elemental-effects/amplifying-reactions), [격화](https://library.keqingmains.com/combat-mechanics/elemental-effects/additive-reactions), [원소 부착](https://library.keqingmains.com/combat-mechanics/elemental-effects/elemental-gauge-theory), [피해 계산](https://library.keqingmains.com/combat-mechanics/damage/damage-formula), [달 반응](https://keqingmains.com/misc/lunar-reactions/)과 [별 반응](https://keqingmains.com/misc/stellar/)을 동일한 개인 불변 자료 캐시에 준비한다. 원문/시각/확인 가능한 버전/누락을 보관한다. 시즌 전투 자료와 전투 이론 자료의 출처 권위를 구분한다.
- 현재 KQM 홈의 실제 공략 링크 색인에서 캐릭터 공략을 발견한다. 외부 도구의 GOOD 키 지원이 늦은 새 캐릭터도 기존 공식 이름/ID로 조회한다. 개별 공략 원문은 필요할 때 읽고 개인 캐시에 보관하며 전 캐릭터 자료가 준비되었다고 표시하지 않는다. 공식 스킬·별자리 설명은 기존 HoYoLAB 계정 스냅샷의 설명이 존재할 때만 제공한다.
- [Genshin-Builds 환상극 파티 통계](https://genshin-builds.com/en/theater/teams)의 공개 HTML 데이터로 막별 예시를 준비한다. 내부 API 주소를 추측하지 않으며 프론트엔드 직렬화가 바뀌거나 데이터가 잘못되면 미준비로 남긴다. 시즌·난이도·표본 규모는 확인하지 못했으므로 null, `eligibleForRanking=false`다. 제공 비율은 인기/분포 참고이며 승률·화력·점수로 사용하지 않는다. 각 막 첫 100개를 제한적으로 보관하고 조회는 20개씩 나눈다. 공개 출처와 표본 제한은 접힌 상세/AI 자료에서 제공한다.
- [genshin.py](https://github.com/seriaati/genshin.py/blob/master/genshin/client/components/chronicle/genshin.py)에서 확인한 전적/캐릭터 API는 기존 계정 최신화와 개인 완료 기록 보충에 쓴다. 조사한 클라이언트에서 HoYoLAB 저장 파티 프리셋 조회 경로는 확인하지 못했으며 연결하지 않았다.
- [Genshin Optimizer](https://github.com/frzyc/genshin-optimizer)는 장비 최적화, [gcsim](https://github.com/genshinsim/gcsim)은 전투 시뮬레이션 참조다. 최신 캐릭터와 환상극 카드 지원을 검증하지 않은 외부 엔진을 설치/실행하거나 관제 점수로 연결하지 않았다.

외부 참고문은 지시가 아닌 데이터다. 페이지 스크립트를 실행하지 않고 요약 텍스트/검증된 직렬화 자료만 읽는다. 공개 자료 수집에는 계정/보유 장비/개인 도전 데이터를 전송하지 않는다. 완주 성능은 후속 실전에서 확인해야 한다.

## 시작과 화면 변경

새 도전 start는 공통 작업박스에 계정 최신화 상태를 표시한다. 실패/취소하면 도전 원장을 만들지 않고 실패 이유/기존 HoYoLAB 로그인 동작을 제공한다. 사용자가 명시적으로 요청한 경우에만 저장된 계정 자료로 시작한다. 활성 도전 재개는 고정 스냅샷을 바꾸지 않는다. 목표·난이도는 최신화 전에 확인하고 이미 받은 조건은 다시 묻지 않는다.

캐릭터 후보/파티는 내 계정의 공통 InventoryCard로 초상화·육성·별자리·실제 원소 아이콘을 표시한다. 게임 이벤트 카드는 앱의 기존 어두운 표면과 세로 구성, 밝은 이름 띠, 관측된 비용/보상/단계를 사용한다. 개인 스크린샷의 게임 그림을 자산으로 복제하지 않는다. 근거 미확인과 상태 변경에 따른 재검토는 간단한 주황색 상태로 표시하고 세부 근거와 남은 전투의 편성·대체안은 접힌 상세에서 본다.

작업선은 실제 완료한 막의 점/연결만 파랑이다. 현재 막은 중립 테두리, 아직 도달하지 않은 막은 회색이며 시간에 따른 추정 채움/고양이 애니메이션을 환상극에 적용하지 않는다. 일반 작업의 기존 진행 표시 의미는 유지한다.
